## 一、发明名称

**一种基于时长预算约束的快慢双通道协同低感知时延语音交互方法及系统**

备选名称：
- 语音交互中基于掩蔽资产时长匹配与动态裁决的时延掩蔽方法
- 一种可牺牲掩蔽音频驱动的低时延全双工语音交互方法

## 二、技术领域

本发明涉及人工智能与人机交互技术领域，具体涉及一种语音交互系统中降低用户感知响应时延的方法及系统，尤其涉及大语言模型（Large Language Model, LLM）驱动的全双工语音交互场景下的时延掩蔽技术。

## 三、背景技术

### 3.1 现有技术方案

**方案一：单通道大模型直接应答（LLM 直答）**

用户语句结束后，经语音识别（Automatic Speech Recognition, ASR）得到文本，送入单个大语言模型生成完整回复，再经语音合成（Text-to-Speech, TTS）播放。

存在问题：
- 大模型首 token 生成时延通常为 1~5 秒，TTS 合成整段回复另需 2~10 秒；
- 用户从"说完"到"听到首个字"的感知时延为 5~15 秒，用户感知为"无响应"或"卡顿"，交互体验不可接受；
- 在回复较长时，若采用整段合成，空洞更为显著。

**方案二：预置固定承接语**

在等待大模型生成期间，播放预先录制的固定过渡语（如"稍等"、"正在为您查询"）。

存在问题：
- 内容机械重复、与语境无关，用户多次交互后产生明显重复感；
- 承接语时长为固定值，无法匹配大模型**可变**的生成时延（有时大模型 1 秒即就绪，承接语播了 3 秒造成冗余；有时大模型 5 秒未就绪，承接语播完出现空洞）；
- 无法根据用户指令内容动态调整。

**方案三：预测性填充语注入（参见 US11704900B2）**

Meta Platforms 公司的 US11704900B2 公开了一种助手系统的预测性会话填充语注入方法：客户端系统接收用户输入后，识别用户输入中引用的**一个或多个实体**，据此提供包含**引用这些实体的**会话填充语的"初始响应"（initial response）；随后由自然语言理解（NLU）模块进行语义分析，识别**一个或多个意图（intents）和一个或多个槽位（slots）**，在初始响应之后提供"完整响应"（complete response）。

存在问题：
- 该方案依赖实体识别与 NLU 意图/槽位管线，面向传统任务型助手架构，无法适配大语言模型的长尾生成时延（LLM 生成时延分布跨度大、不可由槽位数量预估）；
- 填充语**引用用户输入中的实体**，导致填充语内容与后续完整响应存在**内容重叠/重复**（例如填充语"关于上海天气，我来查一下"，完整响应"上海今天晴，25 度"——实体"上海天气"被重复）；
- 未解决填充语**播放时长与等待时长不匹配**的问题；
- 未给出用户打断（barge-in）时填充语与后续请求的处置策略。

**方案四：流式大模型边生成边播**

大模型以流式方式生成，首句生成后立即合成播放。

存在问题：首个句子的播放仍受首 token 生成时延限制（1~5 秒空窗依然存在），仅压缩了后续句子的等待，未解决**首次出声**的时延问题。

**方案五：端到端全双工语音大模型**

采用端到端语音大模型直接进行双工交互（如 Thinker-Talker 架构）。

存在问题：
- 模型为黑盒，输出内容与时序不可控、不可审计；
- 训练与推理成本高，且难以与既有业务系统（工具调用、知识库）对接；
- 难以在已有级联（ASR→LLM→TTS）管线上增量落地。

**方案六：打断内容呈现（参见 US11605384B1）**

Nvidia 公司的 US11605384B1 公开了在人说话期间呈现插话内容（interrupting content）的全双工通信方案：接收语音数据并用语言模型评估，若满足条件则在人说话期间呈现内容。

存在问题：其场景为**在用户说话期间**呈现内容以提升双工感，不涉及用户语句结束后、系统应答前的**生成空窗掩蔽**问题；亦未涉及掩蔽内容的时长控制与请求取消/降级。

### 3.2 现有技术的共同缺陷总结

| # | 缺陷 | 影响 |
|---|------|------|
| D1 | 首字空窗 1~5s 无法掩蔽 | 用户感知无响应 |
| D2 | 掩蔽内容时长为固定值或不可控 | 时长不匹配 → 冗余或空洞 |
| D3 | 掩蔽内容与最终回复内容重复 | 语义冗余，体验差 |
| D4 | 打断后需重新生成 | 算力与流量浪费 |
| D5 | 单通道架构，掩蔽成本高 | 无法用小模型低成本掩蔽 |

## 四、发明内容

### 4.1 本发明要解决的技术问题

针对上述缺陷，本发明要解决的技术问题是：

**如何在用户语句结束、系统应答之前的生成空窗期内，以与空窗时长自适应匹配的低成本内容进行时延掩蔽，实现低感知响应时延、内容不重复、打断零重生成成本的语音交互。**

具体分解为四个子问题：
1. **如何用远低于大模型的成本产生掩蔽内容**（解决 D5）；
2. **如何使掩蔽内容的播放时长与不可预知的大模型生成时延自适应匹配**（解决 D2）；
3. **如何保证掩蔽内容与最终回复内容不重复**（解决 D3）；
4. **如何在用户打断时以零重生成成本终止掩蔽并处置在途请求**（解决 D4）。

### 4.2 技术方案

本发明提出一种快慢双通道协同架构：以**快通道**（第一模型，小参数模型）生成**掩蔽资产**（承接语和/或意图转述）即时出声，以**慢通道**（第二模型，大参数模型）并行生成完整回复；掩蔽资产的输出长度受**时长预算约束**；两通道产物经**融合裁决**后串行播放；掩蔽资产具备**可牺牲语义**，播放期被用户插话即停即弃。

#### 4.2.1 总体流程

```
用户语音 → ASR 定稿 → [策略判定] ┬─ 快通道（第一模型）→ 掩蔽资产（承接语/转述）
                                │                              ↓ TTS
                                └─ 慢通道（第二模型）→ 完整回复 → 融合裁决 → 播放链
```

**步骤 S1（输入定稿）**：接收用户语音输入，经 ASR 得到文本表示（定稿）。

**步骤 S2（双通道并行启动）**：以文本表示为输入，**并行**启动快通道与慢通道：

- **S2.1 快通道**：以第一模型生成掩蔽资产，掩蔽资产包括承接语（语境相关的过渡语）和/或意图转述（对用户意图的复述确认）。第一模型为参数量小于第二模型的轻量模型，其生成时延显著低于第二模型（实测 300~500ms）。
- **S2.2 慢通道**：以第二模型生成完整回复，采用分句流式输出。
- **S2.3 时长预算约束**：第一模型的生成受时长预算约束——该预算依据慢通道的预计就绪时刻动态确定，使掩蔽资产经 TTS 合成后的**播放时长 ≥ 慢通道的预计空窗**。

**步骤 S3（融合裁决）**：监测慢通道就绪时刻，与掩蔽资产播放进度比较，动态裁决：

- **S3.1 就绪衔接**：若慢通道在掩蔽资产播放结束前（或结束时）就绪 → 掩蔽资产播完无缝接播慢通道首个分句，并执行**语义重叠剪裁**（删除慢通道回复中与掩蔽资产语义重复的内容）；
- **S3.2 未就绪续掩蔽**：若掩蔽资产播放结束时慢通道仍未就绪 → 续发下一掩蔽资产（如意图转述，或追加承接语），循环直至慢通道就绪。

**步骤 S4（可牺牲语义与打断联动）**：掩蔽资产具备可牺牲语义——在掩蔽资产播放期间，若语义语音活动检测（Semantic VAD）判定用户发生打断（barge-in），则：

- 立即停止掩蔽资产播放并**丢弃**该掩蔽资产（不触发任何重新生成）；
- 同步**取消或降级**在途的慢通道请求（取消：终止第二模型生成；降级：保留已生成部分作为上下文）。

#### 4.2.2 关键机制详述

**（1）时长预算约束生成（核心差异特征）**

第一模型的训练目标**显式建模输出长度**：以输出 token 数映射至 TTS 播放时长，使掩蔽资产的播放时长可控。训练样本中包含长度标签，训练损失包含"目标时长与实际合成时长偏差"项。

时长预算的确定方式（任一或组合）：
- 依据慢通道的**历史生成时延统计**（如分位数 P50/P90）；
- 依据大模型**已生成 token 数 / 已耗时**的在线估计；
- 依据掩蔽资产合成时长与慢通道剩余等待时间的实时差值，动态追加第二掩蔽资产。

> 与一般知识蒸馏的本质区别：一般蒸馏目标是"输出内容接近教师模型"；本方案训练目标是"输出**时长**匹配待掩蔽空窗"——时长是一等训练目标，而非副产物。

**（2）掩蔽资产去内容化（与 US11704900B2 相反的哲学）**

本发明的承接语**不引用用户指令的具体内容**（实测采用 6~10 字通用过渡语，如"好的，我马上处理"），其目的是**避免与慢通道完整回复内容重复**；相应地，慢通道被配置为"不要开头客套、首句 15 字内给出结果"——两通道内容分工、互不重复。

与之对比，US11704900B2 的填充语**引用实体**，天然与完整响应内容重叠。

**（3）分句流式合成与并发限流**

慢通道回复按标点边界切分为 15~40 字的子句，各子句的 TTS 并行合成（受并发上限约束，实测 2 并发以避免服务端限流），使**合成速度快于播放速度**，形成流水线，消除句间空洞。

**（4）挂等机制（防快慢重叠）**

播放链维护挂等标记：当慢通道分句先于掩蔽资产就绪时，**仍挂等**掩蔽资产播放完毕后再接播（而非直接播放），保证严格串行、无重叠；并设超时兜底（若掩蔽资产超时未到达则直接播放，防卡死）。

**（5）策略可插拔**

融合策略抽象为可插拔接口，至少包括：
- **快慢融合策略**：启用掩蔽资产 + 慢通道完整回复；
- **慢通道直达策略**：禁用快通道（第一模型零调用），慢通道直接输出（保证两套机制的独立性）。
切换可热生效而不中断服务。

### 4.3 有益效果

| 效果 | 实测数据（rule 模式全链路） | 对照 |
|------|------------------------------|------|
| 感知响应时延（说完→首次出声） | **2.1~2.5s** | 单通道直答 5~15s |
| 掩蔽资产生成时延 | 316~533ms（第一模型） | 第二模型首 token 317~465ms + 整段 TTS 数秒 |
| 掩蔽资产 TTS 首块 | 434~500ms | — |
| 空洞控制 | <0.1s（6~10 字承接语） | 1 字承接语空洞 2.7s |
| 分句合成后首句就绪 | 2.1s（原整段 10.6s，**快 5.4 倍**） | 整段合成空洞 7.6s |
| 打断成本 | 掩蔽资产即停即弃，**零重生成** | 打断后重生成，浪费一次完整推理 |
| 内容重复 | 无（两通道内容分工） | 实体引用填充语与完整响应重复 |

其它效果：
- 与既有级联管线（ASR→LLM→TTS）兼容，可增量落地，无需端到端重训；
- 全链路可观测（快慢通道时延分列统计、播放链事件可追踪），输出可审计；
- 服务端算力成本可控（掩蔽资产由小模型生成；打断时取消大模型请求以节省算力）。

## 五、具体实施方式

### 实施例 1：智能家居语音助手（快慢融合策略）

**系统组成**：
- 前端：麦克风阵列 + 浏览器/终端音频采集，播放链（流式 PCM 播放 + 整段音频队列）；
- 服务端：ASR 模块（流式识别）、语义 VAD 模块（判停 + 打断判定）、融合策略模块、快通道（本地轻量模型或云端小模型）、慢通道（云端大模型）、分句 TTS 模块、统一事件队列。

**流程**：

1. 用户说"把客厅的灯打开"；
2. 语义 VAD 判停（例：静音 800ms）后，前端切段上传；
3. ASR 流式识别输出文本"把客厅的灯打开"；
4. 融合策略判定为指令类 → 启动快通道；
5. 慢通道（大模型）并行启动，流式生成完整回复"客厅的灯已经打开了"；
6. 快通道（小模型）受时长预算约束生成承接语"好的，我马上处理"（8 字，TTS 播放约 1.5s，覆盖慢通道预计空窗）；
7. 前端立即播放承接语 → 用户感知响应时延约 2.2s；
8. 慢通道首句就绪（约 2.3s）→ 承接语播完后无缝接播"客厅的灯已经打开了"；
9. 若用户在第 7 步播放期间说"等等，是卧室"→ 语义 VAD 判定 barge-in → 立即停播并丢弃承接语 → 取消在途慢通道请求 → 进入新轮次。

**实测时延分项**：

| 环节 | 实测 |
|------|------|
| 快通道承接语生成 | 316~533ms |
| 慢通道首 token | 317~465ms |
| 承接语流式 TTS 首块 | 444~500ms |
| 慢句分句流式首块 | 434~461ms |
| 响应（说完→开始播） | 2.1~2.5s |
| 完整回复结束 | 12~13s |

### 实施例 2：掩蔽资产未就绪的续掩蔽

当慢通道在承接语播完时仍未就绪（如极端长尾生成、服务端拥塞）：

1. 承接语播放结束前（例：剩余 200ms），系统检测慢通道无就绪分句；
2. 快通道续发第二掩蔽资产——**意图转述**（"您是想让我把客厅的灯打开，对吗？"）；
3. 意图转述播放期间慢通道就绪 → 无缝接播完整回复，并执行语义重叠剪裁（删除与转述重复的部分）；
4. 若转述播完仍未就绪 → 可再追加掩蔽资产或切换为静默等待（按配置）。

### 实施例 3：慢通道直达策略（可插拔的另一策略）

配置为"慢通道直达"时：
- 融合策略的 `should_fast` 恒返回否 → 第一模型**零调用**（日志可验证）；
- 慢通道直接输出分句并播放；
- 适用于：用户明确要求简短、或快通道不可用的降级场景。

### 实施例 4：快通道失败降级

若快通道异常（模型不可用、超时）：
- 记录异常并跳过掩蔽资产；
- 慢通道分句索引自 0 起（等价于"直达"语义）；
- 前端播放链无需感知策略差异（索引语义自洽）。

### 关键参数（实测优选值）

| 参数 | 优选值 | 依据 |
|------|--------|------|
| 承接语长度 | 6~10 字 | 1 字空洞 2.7s；14 字压缩慢句首句响应 |
| 分句子句长度 | 15~40 字 | 过长（200 字整段）合成 10.6s |
| TTS 并发上限 | 2 | 5 并发触发服务端 429 限流 |
| 挂等超时兜底 | 2s | 快通道失败/策略误判时不卡死 |
| 流式完成兜底 | 300ms | 完成信号晚到场景 |

## 六、权利要求书（草案）

### 权利要求 1（独立权利要求·方法）

一种低感知时延语音交互方法，其特征在于，包括以下步骤：

S1、获取用户语音输入的文本表示；

S2、以所述文本表示为输入，并行启动快通道与慢通道：
- 所述快通道以第一模型生成掩蔽资产，所述掩蔽资产包括承接语和/或意图转述，且所述第一模型生成所述掩蔽资产的输出长度受时长预算约束，所述时长预算依据所述慢通道的预计就绪时刻确定，以使所述掩蔽资产经语音合成后的播放时长不小于所述慢通道的预计空窗时长；
- 所述慢通道以第二模型生成完整回复，所述第二模型的参数量大于所述第一模型；

S3、监测所述慢通道的就绪时刻，并与所述掩蔽资产的播放进度进行比较，执行融合裁决：
- 当所述慢通道在所述掩蔽资产播放结束时就绪，则在所述掩蔽资产播放结束后接播所述慢通道的输出，并对所述慢通道的输出执行语义重叠剪裁，以删除与所述掩蔽资产语义重复的内容；
- 当所述慢通道在所述掩蔽资产播放结束时未就绪，则继续输出下一掩蔽资产，直至所述慢通道就绪；

S4、在所述掩蔽资产的播放期间，若检测到用户打断事件，则停止播放并丢弃当前掩蔽资产且不触发该掩蔽资产的重新生成，同时取消或降级所述慢通道的在途请求。

### 权利要求 2（时长预算约束）

根据权利要求 1 所述的方法，其特征在于，所述时长预算通过以下方式之一或其组合确定：

a) 依据所述慢通道的历史生成时延统计量的分位数确定；
b) 依据所述慢通道已生成内容的量与其已耗时的在线估计确定；
c) 依据所述掩蔽资产的合成播放时长与所述慢通道剩余等待时间的实时差值确定，并在差值为负时继续输出下一掩蔽资产。

### 权利要求 3（第一模型的训练）

根据权利要求 1 所述的方法，其特征在于，所述第一模型经训练得到，其训练目标包含时长约束项：以所述第一模型的输出长度映射至经语音合成后的播放时长，并将目标时长与实际合成时长的偏差计入训练损失，使所述第一模型生成的掩蔽资产的播放时长可控。

### 权利要求 4（承接语去内容化）

根据权利要求 1 所述的方法，其特征在于，所述承接语为不引用所述用户语音输入中实体及指令具体内容的通用过渡语；且所述慢通道被配置为不输出开头客套语、并在首个分句内给出回复结果，以使所述承接语与所述完整回复的内容不重复。

### 权利要求 5（掩蔽资产类型）

根据权利要求 1 所述的方法，其特征在于，所述掩蔽资产包括第一掩蔽资产与第二掩蔽资产，所述第一掩蔽资产为承接语，所述第二掩蔽资产为意图转述，所述意图转述用于在所述慢通道未就绪时对用户意图进行复述确认。

### 权利要求 6（分句流式合成）

根据权利要求 1 所述的方法，其特征在于，所述慢通道的完整回复按标点边界切分为子句，各子句的语音合成并行执行且受并发上限约束，使合成速度快于播放速度。

### 权利要求 7（挂等机制）

根据权利要求 1 所述的方法，其特征在于，当所述慢通道的输出先于所述掩蔽资产就绪时，将所述慢通道的输出置为挂等状态，在所述掩蔽资产播放结束后再接播；并设置超时阈值，超过所述超时阈值时直接播放所述慢通道的输出。

### 权利要求 8（打断联动）

根据权利要求 1 所述的方法，其特征在于，所述用户打断事件由语义语音活动检测模型判定；所述取消指终止所述第二模型的生成，所述降级指保留所述第二模型已生成的内容作为后续轮次的上下文。

### 权利要求 9（策略可插拔）

根据权利要求 1 所述的方法，其特征在于，还提供可切换的慢通道直达策略，在所述慢通道直达策略下所述第一模型不被调用，所述慢通道的输出自首个索引开始播放；所述策略的切换为在线热切换。

### 权利要求 10（系统）

一种低感知时延语音交互系统，其特征在于，包括：

- 语音识别模块，用于获取用户语音输入的文本表示；
- 融合策略模块，用于并行启动快通道与慢通道；
- 快通道模块，包含第一模型，用于生成输出长度受时长预算约束的掩蔽资产；
- 慢通道模块，包含参数量大于所述第一模型的第二模型，用于生成完整回复；
- 融合裁决模块，用于监测所述慢通道的就绪时刻并与掩蔽资产的播放进度比较，执行就绪衔接、语义重叠剪裁或续掩蔽；
- 播放控制模块，用于串行播放所述掩蔽资产与所述慢通道的输出，并在检测到用户打断事件时停止并丢弃当前掩蔽资产、取消或降级所述慢通道的在途请求。

### 权利要求 11（电子设备/存储介质）

一种电子设备，包括处理器与存储器，所述存储器存储计算机程序，所述处理器执行所述计算机程序时实现权利要求 1 至 9 任一项所述的方法。

一种计算机可读存储介质，其上存储计算机程序，所述计算机程序被处理器执行时实现权利要求 1 至 9 任一项所述的方法。

## 八、与最接近现有技术的区别（发明点论证）

| 对比项 | US11704900B2（Meta） | 本发明 |
|--------|----------------------|--------|
| 架构 | 单管线 + NLU 意图/槽位 | **双模型异构通道并行** |
| 掩蔽内容来源 | 识别实体后生成填充语 | 第一模型受**时长预算约束**生成 |
| 掩蔽内容与最终回复关系 | **引用实体 → 内容重叠** | **刻意为通用过渡语 → 不重复** |
| 时长控制 | 无 | **显式建模输出长度，播放时长匹配空窗** |
| 多级掩蔽 | 无 | **承接语 → 意图转述 续掩蔽** |
| 打断处置 | 未涉及 | **可牺牲音频：即停即弃 + 取消/降级** |
| 裁决时机 | 未涉及 | **按慢通道就绪时刻动态裁决 + 语义重叠剪裁** |

| 对比项 | US11605384B1（Nvidia） | 本发明 |
|--------|------------------------|--------|
| 场景 | 用户**说话期间**呈现插话内容 | 用户**说完后、系统应答前**的生成空窗掩蔽 |
| 目的 | 提升双工交互感 | 消除首字空窗、降低感知时延 |
| 时长/取消机制 | 未涉及 | 时长预算约束 + 请求取消/降级 |

**发明点归纳**：单项技术（会话填充语、双模型、流式合成、打断处理）均有在先文献，但"**时长预算约束的自训练快通道 + 承接语去内容化 + 按慢通道就绪时刻动态裁决 + 可牺牲音频取消/降级**"这一**组合**未见在先公开，独立权利要求应将上述四项特征同时写入以确立新颖性与创造性。
