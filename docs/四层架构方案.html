四层架构方案：语音交互 · 意图路由 · 小脑 · 大脑

版本 v0.2　·　2026-10-25　·　适用范围：级联全双工语音助手（Talker–Thinker 两级）

本版决策：L2 规则先行、Jev 第二阶段；L3 选 8B 级（Qwen3.5-9B）；L2 写操作走口头确认。

口径约定：文中标注【实测】的为项目内真实调用或代码级验证；标注【官方】的取自厂商或论文原文；

标注【估算】的为工程推算，须在 P0 阶段用实测替换。未标注来源的对比数字一律不进评审材料。

1. 方案总览

1.1 设计目标与约束

本方案要在保持级联架构（ASR → LLM → TTS）不变的前提下，引入一个像 Gander 那样"能跑任务闭环"的前端，

但不把交互控制训练进模型。目标与约束如下：

目标量化表述约束
低时延说完→开始播 p50 ≤700ms、p95 ≤1200ms判停与 ASR 已占 ~700ms，路由与首字必须落在剩余预算内
不抢话抢话率不高于当前基线打断判定只能由 L1 的确定性事实驱动
能闭环简单任务本地完成，复杂任务可上交本地完成不等于本地裁决，裁决权在 L2
可解释每个 turn 可回答"为什么走这条路"决策与台词分离，各自可单独评测
可迭代换模型与开能力必须能分别验证阶段划分必须单变量

三条不可让渡的约束：

  • 模型不做时间管理：要不要先出承接语取决于预期等待时长，模型看不到时钟。
  • 编排器不做语义判断：编排器只按规则与时延预算调度，不解释用户说了什么。
  • 确定性事实不进模型：播放状态、是否插话、是否拒识由 L1 的规则与状态机产出（项目内已实测：模型会无视 prompt 中的确定性声明）。

    • 1.2 四层职责与边界

    层名称唯一职责输入输出不做
    L1语音交互判断"要不要响应、是否打断、听没听清"音频流、播放状态文本 + 状态事件不做语义理解、不选模型

    L4大脑执行复杂任务并回传结果task_starttask_resume不直接对用户说话

    边界判据（用于评审时吵不清的场合）

    问题判据归属
    要不要先出承接语取决于预期等待时长编排器（横切）
    这句话该谁答取决于语义与风险等级L2
    现在要不要停播取决于声学与播放状态L1
    这句怎么说取决于措辞与素材L3
    这个任务怎么做取决于业务与权限L4

    1.3 系统架构图

    图中三条要点：

  • 往返路径：L1 产出"文本 + 状态事件"，L3 产出"播报文本"回到 TTS——两条链路在编排器处对齐，不互相等待。
  • 派活与回传分离：L3 → L4 只有 task_start，L4 → L3 只有 task_resume（结论句 + 关键字段），L3 永远拿不到全量中间状态。
  • 横切编排器：节奏、事件序号、取消树、授权域、埋点都在这一列，四层里任何一层都不自行管理时间。

    • 1.4 端到端时延预算

    阶段预算（ms）依据归属
    判停300–800项目实测 800ms 静音判停；语义 VAD 下可压到 300L1
    ASR final350–450流式 fun-asr final ≈0.4s【实测】L1
    路由判定≤300规则 <10ms；判别模型 p50 270–310ms【官方/独立】L2
    承接语首字≤600（从说完算）模板池预合成：选模板 + 播放启动 ≤150ms【估算】编排器
    模型生成句首字（转述/直答）≤900（从素材就绪算）9B 首 token 250–350 + TTS 首包 300–600【估算，须 P0 实测】L3
    工具窗口600–2100决策 450（9B）+ 执行 timeout 1500L3
    后台首句800–3000慢通道首 token ≈450ms，整句就绪 1–3s【实测】L4
    强制升级>3000超预算换长承接语 + 上报编排器

    关键结论：路由 300ms 不必挤进 150ms 预算——承接语可与路由并行合成，

    只要承接语在路由完成前开始播，这 300ms 对用户不可感知。

    1.5 五条设计原则

  • 指令与台词分离：L2 输出指令、L3 输出句子；两者不共用一次模型调用。
  • 单变量迭代：换模型、开工具、加转述必须分阶段验证（沿用《Talker直答与工具调用方案》的定级）。
  • 契约先行：每层交界都有 schema 与序号，晚到事件一律丢弃而不是插播。
  • 宁可慢不可错：误直答的代价远大于多等 1 秒，默认保守。
  • 可观测即功能：每 turn 一条 trace，指标出分布不出平均值。

    3. L2 意图路由层

    3.1 职责与边界

    L2 只回答一个问题：这一轮该本地处理，还是该交给大脑。它输出的是指令，不是话，也不是具体工具。

    输出 action含义附带字段
    answer_local素材已在本地可得（记忆检索 / FAQ / 纯格式化）material
    tool_local本地域内的只读或可逆写工具tool_grant（allowed / max_steps / risk_ceiling）
    dispatch交给 L4 执行task_spec（意图 / slots / 预算 / 是否可取消）
    drop附和、噪声、回声reason

    与 L3 的分工：L2 决定"授权哪些工具"，L3 决定"用哪个、参数填什么"。

    判据：新增一个工具时改的是授权表一行，还是改 L2 的判定逻辑？后者说明路由正在回流，必须纠正。

    3.2 可计算判据

    判据条件结论
    本地可解无需外部信息 ∧ 单轮可解 ∧ 答案 ≤30 字 ∧ 无副作用answer_local
    本地工具命中白名单 ∧ 参数单层 ∧ 预计 <1.5s ∧ 风险 ≤L1tool_local
    必须上交步数 >1 ∨ 需业务系统 ∨ 命中 L3 风险 ∨ 置信度低于阈值dispatch
    丢弃附和词 / 噪声转写 / 回声drop

    风险分级（全方案唯一标准）

    级例子允许 L3 本地执行处理
    L0时间、单位换算、日期推算是无需确认
    L1天气、查询类只读工具是带 timeout，失败即降级
    L2设提醒、开关灯（可逆）是播报确认 → 用户确认后执行
    L3下单、支付、门锁否一律归 L4

    判据一句话：做错了能不能一句话撤回。不能 → L4。

    3.3 三级判定链路

    asr_final
  ├─① 规则层（毫秒级）
  │    白名单 / 槽位正则 / 长度与语气词 / 已确认任务续接
  │    命中 → 直接出 directive（覆盖约 40–60% 的高频请求【估算，须用日志统计替换】，目标是"确定的不犹豫"）
  ├─② 判别模型层（p50 270–310ms）
  │    Jev（托管）或 自建 Qwen + logits 约束
  │    一次请求并行问多个原子问题，代码组合
  └─③ 兜底层
       模型超时 / 低置信 / 解析异常 → 默认 dispatch（宁可慢不可错）

    三层是串联短路，不是投票：规则命中就不问模型；模型失联就走保守兜底。

    这条设计直接复用项目里"高能力组件失败 → 回退低能力规则"的教训：

    回退路径必须有保守默认，且要打 degraded 标记，否则误判面会放大。

    自研 logits 判别器Qwen3.5-4B自研完全可控推荐作为内网主路径

    自建的核心技巧（比"换成大模型"更有效）

  • logits 投影代替自由生成：共享前缀 → 取 next-token logits → 只在候选集上 softmax → 类型化决策。

    • 好处：零 JSON 语法错误、延迟低、可给概率。

  • 候选集在解码期屏蔽：未授权选项不参与 softmax，等价于"物理上不可能输出错工具"。
  • 校准要自己做：官方明确不对客户数据微调；自建后必须重新标定阈值（ECE + 选择性预测曲线）。

    • 3.6 置信度与阈值分级

    置信区间含义动作
    高（conf ≥0.9 且 p≥0.9）明确自动执行（仅 L0/L1）
    中（0.6–0.9）有倾向L2 写操作必须先确认；否则上交
    低（<0.6）无把握一律 dispatch，不硬答

    阈值不设单一数字，按动作后果分级：

    动作阈值理由
    L0 本地格式化0.6错了也就是多说一句
    L1 只读工具0.8错了会答非所问
    L2 可逆写0.9 + 口头确认（流程见 3.10）错了要撤回
    L3 有副作用不适用不走模型判定，直接归 L4

    3.7 鲁棒性与注入防护

    JevOut 的结论（31 个词可翻转 61.4%–73.2% 的决策）对路由是致命问题，因为路由的 state 里必然包含用户原话。

    三条硬措施：

  • 结构隔离：state 用 JSON 字段承载（{"user_text": "...", "slots": {...}}），用户内容只出现在被引用的字段里，

    • 题目模板固定，不允许用户文本改写问题本身。

  • 问题原子化：每题只问一件事（"这句是否在请求外部信息"），不把多个因素塞进一题——单题被带偏的影响面更小。
  • 高风险二次校验：L2 及以上动作，第二跳用另一组问题交叉验证；两跳不一致 → dispatch。

    • 3.8 输出契约

    字段类型必填说明
    turn_idstring是一次用户输入一个 turn
    actionenum是answer_local / tool_local / dispatch / drop
    confidencefloat是0–1，最终决策的置信度
    route_sourceenum是rule / model / fallback（用于归因）
    materialobject否answer_local 时给结论句、要点、关键数字
    tool_grantobject否allowed / max_steps / risk_ceiling / per_tool_timeout_ms
    task_specobject否意图、slots、预算、可取消级别
    budget_msint是本 turn 的剩余预算，编排器据此分档
    degradedbool是是否走过降级路径

    3.9 评测方案

    指标定义目标
    路由准确率与人工标注一致≥95%
    误直答率该上交却本地答了<1%
    误派活率本可本地处理却上交<20%（体验指标，可放宽）
    选择性预测p≥0.9 时的准确率（coverage-accuracy）≥95%，且覆盖 ≥60%
    路由时延p50 / p95≤300ms / ≤400ms
    注入鲁棒性加干扰后翻转率<10%

    评测集构造：300–500 条真实语音转写，分层抽样：

    分层占比用途
    常规指令40%主指标
    近邻易混（同一问法不同对象）20%检验槽位与指代
    需要多步/业务系统15%检验上交判断
    附和/噪声/回声15%检验 drop
    拒识与残缺句10%检验澄清触发

    3.10 写操作的口头确认流程

    适用：L2 可逆写（设提醒、开关灯、调温度）。L3 有副作用一律不走本流程（归 L4）。

    步动作归属
    1判定 tool_local 且 risk=L2 → 不执行，下发 clarify 指令L2
    2播确认问句，必须复述关键参数（"明早七点提醒带伞，对吗"）L3
    3用户口头应答 → 语义 VAD 判状态 + ASR 出文本L1
    4判定确认意图：明确肯定 → 执行；明确否定 → 取消；不确定 → 重问一次L2
    5执行后播回执（"设好了"）L3
    68s 无应答 → 作废，播"那这次先不设了"编排器

    四条硬规则：

    规则理由
    只接受明确肯定词表（是/对/好/可以/没问题/嗯对）"嗯"可能是 backchannel；项目实测单字歧义模型判不准（"什么？"被判成 backchannel）
    确认问句必须复述关键参数用户改主意时能当场发现
    只重问一次防死循环与话痨
    确认期内出现噪声/残句/未判停 → 视为未确认宁可作废，不可误执行

    应答词表（初版，须用真实录音扩充）：

    类别示例处理
    肯定是、对、好、可以、没问题、嗯对执行
    否定不用、算了、不是、取消取消并播"好的，已取消"
    歧义嗯、啊、嗯？重问一次（仅一次）
    无关别的话/背景人声视为未确认，超时作废

    审计要求：每次确认都要落一条记录（ASR 文本、VAD 状态、判定结果、是否执行），

    用于事后复盘误确认。

    3.11 分阶段落地

    阶段内容出口条件
    P0规则层 + 埋点规则覆盖率 ≥40%，误判可归因
    P1口头确认流 + 写操作白名单误确认 0，超时作废正确
    P2Jev 判别接入（第二阶段，非前置依赖）路由准确率 ≥95%，p95 ≤400ms
    P3置信度阈值标定误直答率 <1%，选择性预测达标
    P4注入鲁棒性加固翻转率 <10%
    P5授权域下发（与 L3 联动）越权调用 0

    规则先行是刻意的：Jev 是境外托管服务（数据在美国西海岸处理、无权重），

    内网不可用时产品必须能只靠规则跑通。因此 Jev 上线只承担"提升覆盖率与边界判断"，

    不承担"唯一依赖"——规则层的降级路径永远保留。

    4. L3 小脑（Talker LLM）

    4.1 职责与产出

    L3 是"嘴"，不是"脑"。它只接受指令与素材，产出播报文本或受限工具调用。

    产出触发指令典型长度硬约束
    承接语beat=fill8–15 字不出现素材外信息、不承诺结果
    进度转述beat=progress≤20 字/段只描述范围与下一步
    结果转述beat=narrate首句 ≤15 字数字与专名原样、去重、不加评价
    直答措辞action=answer_local≤30 字只能用 material 里的事实
    澄清话术action=clarify≤15 字2–3 个变体轮换
    受限工具调用action=tool_local + grant—只能选 allowed 内的工具，单步

    4.2 模型选型

    4.2.1 能力需求到规模的判据

    能力门槛结论
    承接语 / 转述 / 措辞低（改写类）1.5–4B 足够
    受限工具调用高（指令遵循 + 严格 JSON + 参数抽取）9B 直接可用；4B 必须约束解码且仍可能漏参【项目实测结论】
    多步规划很高不放 L3，归 L4

    4.2.2 基座候选

    候选参数优势风险结论
    Qwen3.5-9B（AWQ 4bit）9B工具调用可靠、少写规则、口语更好；原生 262k 上下文首 token +100–150ms、AWQ ≈6GB【估算】默认基线（2026-10-25 决策）
    Qwen3.5-4B4B首字最快、显存小工具需严格约束解码，仍可能漏参备选：首字预算吃紧时
    现有 qwen9.30（4B 微调版）4B已有业务语料适配原为"直答+工具"训练，需重新对齐 L3 职责仅作对照 / 初始化对照
    Qwen3.5-0.8B0.8B极快转述易失真、口语生硬仅用于承接语专用小模型（双模型方案）

    选型结论：Qwen3.5-9B（8B 级）单模型为主路径（用户 2026-10-25 决策），工具调用不再依赖"规则兜底 + 约束解码硬撑"；

    4B 保留为首字预算吃紧时的降级方案，切换必须按单变量原则单独验证，不得与开工具同时进行。

    代价是首字 +100–150ms，由承接语覆盖（见 4.7.2 的 E 分档）。

    4.2.3 部署形态与资源

    项9B 主路径4B 备选口径
    权重精度AWQ 4bit ≈6GB / FP8 ≈9–10GB / BF16 ≈18GBBF16 ≈8GB / AWQ 4bit ≈3GB【估算】
    推理引擎vLLM + --enable-auto-tool-choice --tool-call-parser --guided-decoding-backend xgrammar同左（工具分支必须开约束）官方文档
    首 token200–300ms（建议 P0 实测，含 4k 上下文）100–200ms【估算，须 P0 实测】
    单卡并发24G + AWQ：约 3–6 并发（4k 上下文）24G：约 4–8 并发【估算】
    上下文原生 262k（转述/长任务友好），但长上下文会抬高首 token32k 级官方模型卡 / 估算
    结构化输出推荐开（防越权工具），非必需必须开（工具 id / 参数枚举候选集屏蔽）见 4.2.4

    部署陷阱（项目已踩）：vLLM 的 tool-call-parser 与模型 chat template 不匹配时工具会完全不可用，

    P1 前必须用 5 条固定 query 单测 parser 往返。

    4.2.4 结构化输出策略

    三层防线，从便宜到贵：

  • 模板 + 候选集：工具 id 只在 allowed 集合上 softmax（解码期物理屏蔽）。
  • JSON schema 约束：参数枚举走 XGrammar，格式错误率归零。
  • 后置校验：参数类型/范围校验失败 → 走澄清话术，不重试超过一次。

    • 4.3 训练必要性判断

    判据：这个能力的失败能否被模板/规则/约束解码兜住？

    能力只靠 prompt建议数据量
    承接语70–80%（模板池可跑，但会越界）模板池为主 + 轻训变体800–1,500 条

    直答措辞80%+（素材已给）可选500–1,000 条
    工具调用9B 明显好于 4B，但仍会漏参必须训（9B 可取下限）2,000–3,000 条
    澄清话术90%（模板足够）不训3–5 个变体

    9B 相对 4B 的实际差别：工具调用从"必须靠规则兜底"变成"训练 + 约束即可稳"，

    因此 P3 阶段可以删掉一批补偿性规则（城市白名单这类），但防御不松：

    L3 风险工具、schema 校验、确认流一个都不能删。

    4.4 训练数据方案

    4.4.1 五类数据与配比

    数据类条数来源目的
    承接语1,200模板 + 强模型扩写学会"只说状态不说内容"、轮播不重复
    进度转述600真实后台片段 + 改写学会每段一句、不剧透未到的部分
    结果转述2,400真实后台输出 + 人工改写数字保真、去重、压成口语
    直答措辞800FAQ/记忆命中样本统一口语风格、控制长度
    工具调用3,000按授权域工具逐个人工构造参数抽取、缺参反问、空结果
    负例（越界/不该说）500人工构造抑制"自创内容"与"话痨"
    合计8,000–8,500—混训集约 0.5–0.7M token【估算】；9B 基座取下限

    4.4.2 承接语数据规范

    每条样本必须满足：

  • 不含指令中的具体内容（不出现"正在为您打开客厅灯"这类执行描述）。
  • 不承诺结果（不出现"马上就好""一定能查到"）。
  • 长度 8–15 字；实测 14 字≈3s，与慢通道首句就绪时间匹配。
  • 同组建 3–5 个等价变体，标注 beat，避免每轮同一句。

    • 4.4.3 转述数据规范

    规则说明反例
    数字原样不改写、不换算、不四舍五入3,200 元 → "三千多"
    实体原样专名不翻译、不缩写"Qwen3.5-4B" → "千问"
    去重同一实体/结论只说一次连续两句都说"三个城市"
    不加评价不出现"很不错/不太理想"转述阶段做判断
    增量每段一句，带 forward-only 语义每段都把前文重念一遍

    4.4.4 工具调用数据规范

    每工具 300–800 条，覆盖五类：

    类型占比例子
    参数完整50%"明天早上七点提醒我带伞"
    缺参需反问15%"设个提醒" → 反问几点
    参数歧义15%同名城市、同名设备
    空结果10%查询无命中
    越界请求10%要求两步 / 要求写操作 → 输出升级建议

    4.4.5 负例与越界样本

    负例是这批数据里最值钱的部分，直接决定"话痨率"和"越界率"：

    负例类型构造方式期望行为
    素材不足只给结论句，问细节说"这个我没拿到"，不编
    不该承接等待 <400ms 的场景直接答，不出承接语
    backchannel用户"嗯/对"不出声（本层不产生输出）
    重复播报同 turn 第二拍换变体或跳过
    噪声转写电视/背景人声由 L2 drop，L3 不接单

    4.4.6 数据量计算

    统计下限（每类）：

    n ≥ z² · p(1−p) / e²        z=1.96, p=0.9
   e=±10% → n≈35（仅冒烟）
   e=±5%  → n≈138
   e=±3%  → n≈384

    工程公式：

    N_total = Σ_t ( K_t × n_min × f_scene × f_neg ) × f_aug

K_t      该类别的子类数（意图数 / 工具数 / 转述形态数）
n_min    每子类下限（推荐 200）
f_scene  信道系数：文本 1.0 / 语音转写 2.0–3.0 / 远场噪声 3.0–5.0
f_neg    难负例系数：1.0（不做）～2.0（1:1 近邻负例）
f_aug    合成折算：合成:真实=1:1 时取 0.6–0.8

    代入本方案：工具 5 个 × 200 × 2.5（语音）× 1.5（近邻负例）= 3,750 条 【估算】→ 9B 基座收敛更快，

    取 2,000–3,000；转述 4 种形态 × 200 × 3.0 = 2,400；承接语 4 类 × 200 × 1.5 = 1,200。

    合计约 8,000 条（9B 取下限）。实际数量以 P2 的单能力饱和实验为准，不用公式硬凑。

    数据规模的两条外部参照：

  • 只学格式/风格，500–2,000 条即可（LIMA 用 1,000 条做出可用对齐【论文】）。
  • 数据"选得对"可抵 3–4.5 倍数据量（GRAPE：1/3 数据 + 半 epochs 超过 Tulu3-SFT 3.5%【论文】）。
  • 重复训练的上限：同一份数据重复 ≤4 个 epoch ≈ 新数据（Muennighoff et al., arXiv:2305.16264【论文】）。

    • 4.4.7 数据质检

    检查项方法门槛
    素材可追溯每条答案的关键事实必须能在 material 找到100%
    长度合规脚本统计字符数分布承接语 8–15 字占 ≥90%
    重复度句级 simhash 去重重复率 <5%
    语言一致性中文（术语可保留英文）抽检 10%

    4.7.1 渲染请求

    字段类型必填说明

    4.7.2 E 分档与 fill 预算

    承接语的来源分两级，这是 600ms 首字预算能成立的关键：

    优先级来源首字耗时何时用
    主路径预合成模板池（每场景 3–5 条，离线合成好）≤150ms（选模板 + 播放启动）默认，第一拍一律用模板
    增强9B 现场生成变体600–900ms第二拍起、或模板池命中度低时

    模型训练承接语仍然有价值：它产出的是"更适合当前场景的变体"，

    用于扩充模板池与第二拍之后的口播，而不是承担第一句。

    垫词的内容判据、禁忌与评测打分卡见《垫词设计与评测》。

    预期首字 E策略备注
    <400ms直接答不出承接语，避免话痨
    400–1200ms单拍承接语8–15 字，约 2–3s
    ≥1200ms多拍轮播 + 进度转述每 2–3s 一句，最多 3 拍
    >3000ms升级话术"这个我查得慢，先给你初步结论"

    fill 预算：单轮 ≤3 拍、总时长 ≤6s；超出即视为设计缺陷（要么预测器不准，要么后台太慢）。

    4.7.3 取消与降级

    场景处理
    播报中用户插话编排器 cancel(turn_id) → L3 停止生成、TTS 停播
    工具执行中插话取消可撤销工具；已确认的写操作不撤回，只停播
    模型超时降级为模板话术（3 条兜底），并打 degraded
    素材缺失说"这个我没拿到"，禁止编造

    7.1 风险与触发信号

    风险影响触发信号对策
    路由与 L3 职责漂移两处都能判，日志无法归因新增工具要改 L3 逻辑owner 标签启动期互斥校验
    承接语与实际结果冲突用户信任受损用户复问率上升承接语禁内容、禁承诺
    晚到事件插播重叠/乱序播放音频重叠告警turn_id + seq，过期丢弃
    层间契约变更未同步静默降级degraded 比例上升schema 版本号 + 契约测试
    数据泄露到训练集评测虚高评测集与训练集重叠训练前做 n-gram 去重
    口头确认误判执行了用户没同意的写操作用户当场否定 / 撤回肯定词表 + 参数复述 + 8s 超时 + 审计日志

    7.2 兜底与回滚

    场景兜底回滚
    判别模型不可用规则层接管 + 默认 dispatch保留上一版权重与阈值
    承接语生成失败三条模板兜底，打 degraded关闭轮播，退回单拍
    工具 parser 不匹配关工具，只走直答回滚 vLLM 启动参数
    越界率超标收紧负例阈值回滚 LoRA 版本
    时延超标降拍数、抬高 E 阈值回滚编排策略表
    确认期用户沉默 / 噪声视为未确认，8s 超时作废并播告知回滚应答词表或收紧阈值

    8.1 训练样本格式（转述示例）

    {
  "beat": "narrate",
  "beat_seq": 2,
  "material": {
    "conclusion": "明天郑州有雨，气温 12 到 18 度",
    "facts": ["降水概率 80%", "东北风 3 级"]
  },
  "said_set": ["明天", "郑州"],
  "output": "明天郑州有雨，气温十二到十八度。降水概率八成。"
}

    8.2 术语表

    术语含义
    directiveL2 输出的行动指令，不含话术
    beatL3 的一次产出单位（承接/进度/转述/直答/澄清）
    fill 预算单轮承接语的最大拍数与总时长
    授权域L2 下发给 L3 的可用工具集合与风险上限
    选择性预测按置信度阈值取舍后，覆盖量与准确率的权衡曲线
    E预期首字时间，编排器分档依据
