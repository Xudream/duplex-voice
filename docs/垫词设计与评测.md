# 垫词设计与评测：任务闭环等待期的响应策略

> 版本 v1.0　·　2026-10-25　·　适用对象：任务闭环型语音交互系统（ASR → 路由 → 小脑 → 大脑 → TTS）
> 与《四层架构方案》配套：那份定义 L3 的表达职责，本文只回答一个问题——**任务结果回来之前，该说什么、怎么评**。
> 口径约定：【论文】取自公开论文原文；【实测】为项目内真实调用；【估算】为工程推算，须实测替换。

## 1. 适用范围与结论

### 1.1 适用场景

| 场景 | 是否适用 | 说明 |
|---|---|---|
| 任务闭环慢（工具/后台 1–10s 返回） | 适用 | 本文主场景 |
| 快慢双通道的承接语 | 适用 | 承接语是垫词的一种特例 |
| 纯闲聊（无工具、无等待） | 不适用 | 不需要垫词，垫了反而话痨 |
| 长任务（>30s，如订行程） | 部分适用 | 需要"进度型"升级，超出本文范围 |

### 1.2 四条结论

1. **有垫词显著优于没有**：多项 2025–2026 研究一致显示垫词缩短感知等待时间【论文】。
2. **上下文相关 > 通用 > 短促 > 无**：只有与当前任务对齐的垫词，才额外带来质量、融洽度、喜爱度提升与更低的恐怖谷【论文】。
3. **技术型反馈会破坏体验**：loading spinner 类提示降低"像人"的评分，把用户从社会心智模型拉到技术心智模型【论文】；语音场景对应"不要让系统说自己在计算"。
4. **垫词必须与最终答案不冲突**：冲突率是硬指标，目标 0%；同时"少发"本身是优化目标，不是垫得越多越好【论文】。

### 1.3 与四层架构方案的关系

| 文档 | 定义 | 位置 |
|---|---|---|
| 四层架构方案 §1.4 | 时延预算（首字 ≤600ms 等） | `docs/四层架构方案.md` |
| 四层架构方案 §4.7 | 渲染请求与 E 分档策略 | 同上 |

## 2. 术语澄清：四种垫词

### 2.1 功能分类

| 类型 | 例子 | 功能 | 时长 | 误用后果 |
|---|---|---|---|---|
| 接收确认 | "好的，我看一下" | 告诉用户"听到了" | 0.5–1.5s | 被当成承诺（用户以为马上有结果） |
| 范围复述 | "我查一下明天郑州的天气" | 证明"听懂了" | 2–3s | 复述错了比不说更糟 |
| 进度反馈 | "查到两个来源，正在核对" | 证明"在推进" | 2–3s | 编造进度等于说谎 |
| 迟疑/语气词 | "呃…""嗯…" | 模拟思考过程 | 0.3–1s | 机械模仿显得假 |

严格说，"呃/嗯"是 disfluency（迟疑），不是进度信息。研究里统称 filler，但**它和"进度播报"不是一类东西**：
前者是韵律层的社交信号，后者是信息层的内容。二者混用会让系统显得"又啰嗦又没进展"。

### 2.2 常见混用与后果

| 混用 | 表现 | 后果 |
|---|---|---|
| 确认当进度 | 只说"好的"，之后 5s 静默 | 用户以为要答了，结果干等 |
| 进度当确认 | 直接播"正在调用天气接口" | 技术暴露 + 用户不关心 |
| 迟疑当缓冲 | 反复"嗯…嗯…" | 显得没把握，降低信任 |
| 复述当答案 | 把用户问题重念一遍 | 用户重复提问或打断 |

**规则：一次等待最多三类垫词各出现一次，且必须按"确认 → 范围 → 进度"顺序推进，不能倒序或跳级。**

## 3. 业界研究结论

### 3.1 有垫词显著优于无垫词【论文】

| 研究 | 规模 | 关键结论 |
|---|---|---|
| ICMI 2025《Please Let Me Think》 | N=90 + N=104（两项 VR 研究） | 言语垫词显著缩短感知等待时间；垫词的"机器感 vs 人感"对时延感知**无直接影响** |
| ACM TAP 2026《Don't Just Fill the Silence》 | N=24，四条件对照 | 所有垫词类型都改善感知响应时间与估计响应时间 |
| arXiv:2609.10372《PACE》 | 75,000 条真实请求（汽车销售机器人） | 以 PTFR（感知首响应时间）为目标，级联把纯 LLM 的 P95 从 0.53s 降到 0.29s |

含义：**垫词的第一价值是"时间感知"，不是"信息传递"**。不垫词时用户感知的等待会长于实际等待。

### 3.2 上下文相关 > 通用 > 短促 > 无【论文】

TAP 2026 的四条件对照（无 / 短促 / 通用 / 上下文相关）：

| 条件 | 感知响应时间 | 垫词质量 | 融洽度 / 喜爱度 | 恐怖谷 |
|---|---|---|---|---|
| 无垫词 | 基线 | — | 基线 | 基线 |
| 短促（"um"） | 改善 | 较低 | 略升 | 略升 |
| 通用（"Let me see"） | 改善 | 中 | 中 | 中 |
| **上下文相关**（贴合当前任务） | 改善 | **最高** | **最高** | **最低** |

这是目前对"什么样的垫词才是好的"最直接的回答：**必须贴着当前任务说**。

### 3.3 技术型反馈的负面效应【论文】

arXiv:2610.23336《Wait for It》（N=18，三种反馈对照）：

- 具身手势（思考动画）> 视觉 loading spinner
- **显式 spinner 反而降低"像人"评分、破坏沉浸**，因为它把用户从社会心智模型切到技术心智模型

语音场景的等价推论：

| 不要做 | 为什么 |
|---|---|
| "哔——"提示音、等待音效 | 技术信号，暴露机器属性 |
| "正在加载 / 正在推理 / 调用工具中" | 用户不关心实现，且提醒他"你在等机器" |
| 倒计时 / 剩余时间显示 | 研究显示剩余时间反馈会**提高挫败感**（相对已用时间反馈）【论文】 |

### 3.4 垫词必须与最终答案不冲突【论文】

PACE 的 filler 控制器指标：

| 指标 | 结果 | 含义 |
|---|---|---|
| filler–answer 冲突率 | **0%**（judged） | 垫词说了 A、答案是 B 的情况必须为零 |
| 小模型调用减少 | **94%** | 只在必要时才发垫词，不是每轮都发 |

冲突的典型形态：

| 冲突 | 例子 |
|---|---|
| 对象冲突 | 垫词"查一下航班"，答案"明天的会议改到三点" |
| 范围冲突 | 垫词"只看天气"，答案还报了空气质量与穿衣建议 |
| 动作冲突 | 垫词"我帮您订"，答案"这个需要您自己确认" |

### 3.5 系统级收益可量化【论文】

PACE 的三项收益（同一系统内）：

| 机制 | 效果 |
|---|---|
| 级联路由 + 垫词 | P95 感知首响应 0.53s → 0.29s |
| 自适应控制器 | 高负载下优于标准 RAG 2.4 倍以上，质量无统计差异 |
| 波动感知缓存 | 时效类问题的过期答案从 86% 降到 0% |

含义：垫词不是孤立技巧，它和"路由 + 缓存"是一套组合；**只做垫词、不做时延治理，收益有限**。

### 3.6 研究空白

| 空白 | 说明 |
|---|---|
| 中文垫词研究几乎没有 | 现有实验以英/日/德语场景为主 |
| 长任务（>10s）的垫词节奏 | 现有研究多为 2–5s 等待窗口 |
| 垫词与任务失败的衔接 | 失败时如何收尾，未见系统研究 |
| 垫词的"持续性"指标 | 多拍轮播的边际收益递减点未知 |

## 4. 好垫词的判据

### 4.1 六条判据

| 判据 | 要求 | 反例 |
|---|---|---|
| 相关性 | 与当前任务的对象/范围一致 | 问天气说"我先看看您的日程" |
| 不越界 | 不含结论、不含承诺、不含评价 | "马上就好""这个肯定没问题" |
| 信息增量 | 至少告诉用户"在做什么/推进到哪" | "稍等""请稍候"（零信息） |
| 长度匹配 | 8–15 字 ≈ 2–3 秒，覆盖实际等待 | 1–4 字（0.5s）后留 2–4s 空洞 |
| 可衔接 | 与最终答案同一套说法 | 垫词说"查航班"，答案说"车次已订" |
| 可轮播 | 同场景 3–5 个变体，每 2–3 秒换一句 | 每次都是"好的，正在为您查询" |

### 4.2 两条工程约束

| 约束 | 说明 |
|---|---|
| 不重复 | 同一轮内不重复同一句；相邻两轮不用同一变体 |
| 可退出 | 结果到达时自然交接（"查到了，明天…"），不说"啊，结果来了"这类元话语 |

## 5. 建议方案

### 5.1 分层策略（按预计等待 E 分档）

| 预计等待 E | 策略 | 内容 |
|---|---|---|
| < 400ms | 不垫词 | 直接答（避免话痨） |
| 400–1200ms | 单拍 | 接收确认 + 范围复述 |
| 1200–3000ms | 轮播 3 拍 | 确认 → 进度 → 安抚 |
| > 3000ms | 升级 | 长垫词 + 明确交代 + 给"先听别的"的出口 |

E 的来源：按 (意图, 工具) 维度维护首字节时间的 EWMA p90；预测误差 >30% 退保守档。

### 5.2 内容配方（四类模板）

| 类型 | 模板 | 长度 | 使用档位 |
|---|---|---|---|
| 确认型 | 好的，我看一下 / 行，我来查 | ≤8 字 | 400ms 起 |
| 范围型 | 我查一下{对象}的{属性} | 8–15 字 | 400ms 起 |
| 进度型 | 找到{数量}个来源，正在核对{维度} | 10–18 字 | 1200ms 起 |
| 安抚型 | 这个有点慢，稍等我一下 | 8–12 字 | >3000ms |

**进度型必须是真进度**：不能让模型自由编造"找到三个来源"。可行做法只有两种：

1. 后台真的按阶段回报（task_progress 事件），垫词只做措辞；
2. 没有真实进度时，退化为范围型（只复述已确认的信息）。

### 5.3 三条硬禁忌

| 禁忌 | 理由 | 替代说法 |
|---|---|---|
| 不承诺时间（"马上/立刻/10 秒内"） | 一旦超时就是失信 | "这个要查一下" |
| 不剧透结论（"明天有雨，我再确认下"） | 用户已拿到答案，垫词失去意义 | "正在查明天的天气" |
| 不解释技术（"模型在推理/调用工具"） | 技术心智模型破坏沉浸【论文】 | "我核对一下" |

### 5.4 生成来源与控制器

| 优先级 | 来源 | 首字耗时 | 何时用 |
|---|---|---|---|
| 主路径 | 预合成模板池（每场景 3–5 条，离线合成） | ≤150ms | 第一拍一律用模板 |
| 增强 | 9B 现场生成（带 fill / progress 两种 task token） | 600–900ms | 第二拍起、模板命中度低时 |

控制器三条规则（对齐 PACE 的"少发"思路）：

1. E < 400ms 不发（省调用）
2. 同一轮最多 3 拍，总时长 ≤6s
3. 生成结果先过冲突检测（见 6.1），冲突即降级为通用句

### 5.5 与 L1/L2/L3 的职责边界

| 决定 | 归属 |
|---|---|
| 要不要垫词、垫几拍 | 编排器（E 分档，确定性规则） |
| 垫词说什么（措辞） | L3 |
| 后台真进度 | L4（task_progress 事件） |
| 用户是否在说、是否被打断 | L1（VAD 状态） |

L3 不判断"要不要垫"，也不编造进度——它只按 beat 指令把素材变成话。

## 6. 评价体系

### 6.1 客观指标（全部可埋点）

| 指标 | 定义 | 目标 |
|---|---|---|
| PTFR（感知首响应） | 用户说完 → 第一个有语义的音频包 | p50 ≤600ms / p95 ≤900ms |
| filler–answer 冲突率 | 垫词与最终答案在对象/范围/动作上矛盾 | **0%** |
| 空洞率 | 等待期间出现 >200ms 静默的轮次占比 | ≤5% |
| 话痨率 | 不必要垫词（E<400ms 仍垫）占比 | ≤10% |
| 重复率 | 同轮重复句，或相邻轮同变体 | ≤5% |
| 长度匹配误差 | 垫词时长与实际等待之差的绝对值（中位数） | ≤500ms |
| 越界率 | 含结论/承诺/评价的垫词占比 | ≤2% |
| 垫词占比（Filler rate） | 垫词轮次 / 总轮次 | 监控值（参照：Gander 51.6% 偏高被官方列为弱项） |

冲突检测的可实现方式（规则优先，成本低）：

```
取出垫词中的实体与动作 → 与最终答案的实体/动作集合求差
差集非空且涉及对象/范围/动作 → 标记冲突 → 降级为通用句
```

### 6.2 主观量表（做 A/B 时照抄）

| 量表 | 问法 | 来源 |
|---|---|---|
| 感知等待时间 | "你觉得刚才等了多久？"（秒） | 多项研究通用做法 |
| 垫词质量 | 1–5 Likert | TAP 2026 |
| 融洽度 rapport | 1–5 | TAP 2026 |
| 喜爱度 likability | 1–5 | TAP 2026 |
| 继续交互意愿 | 1–5 | TAP 2026 |
| 恐怖谷 | 1–5（越高越不适） | TAP 2026 |
| 透明度 | 用户是否清楚系统在做什么（1–5） | ICMI 2025 |

### 6.3 生成质量指标与其局限

若自训垫词模型，可用 arXiv:2509.20237 的指标体系：

| 指标 | 用途 | 局限 |
|---|---|---|
| frequency | 检验垫词频率是否接近人类 | 中文无公开基线 |
| diversity | 变体是否足够 | 无法判断"变体是否得体" |
| frequency-weighted perplexity | 用词是否自然 | 依赖参考模型 |
| BERTScore / BLEU | 与参考句相似度 | **垫词极短，噪声极大**，只能抓"明显崩坏" |

**结论：这些是代理指标，不能替代主观评分。**

### 6.4 打分卡（0–5 分制）

| 维度 | 权重 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|---|
| D1 相关性 | 25% | 对象/范围与任务完全一致 | 大致相关但不精确 | 说错对象或泛泛而谈 |
| D2 不越界 | 25% | 无结论、无承诺、无评价 | 措辞略含糊 | 提前给结论或承诺时间 |
| D3 信息增量 | 15% | 明确说了进度或范围 | 仅说了"在查" | 纯"稍等" |
| D4 长度节奏 | 15% | 与等待匹配（±0.5s） | 偏差 0.5–1.5s | 太短留空洞或太长拖沓 |
| D5 衔接性 | 10% | 与最终答案同一套说法、自然交接 | 略有跳脱 | 说法不一致或突兀切换 |
| D6 多样性 | 10% | 与同轮/近轮不重复 | 偶尔重复 | 每次都同一句 |

计分规则：

```
总分 = 0.25×D1 + 0.25×D2 + 0.15×D3 + 0.15×D4 + 0.10×D5 + 0.10×D6
D2 为否决项：D2 = 1 时整条判不合格，不参与加权
合格线：总分 ≥ 3.5，且 D1/D2 均 ≥ 4
```

## 8. 风险与反模式

### 8.1 五个反模式

| 反模式 | 后果 | 纠正 |
|---|---|---|
| 每轮都垫 | 话痨，用户嫌烦 | E < 400ms 不发 |
| 垫词越长越好 | 拖沓，且占用回答时间 | 8–15 字，覆盖等待即可 |
| 让模型编进度 | 说"找到三个来源"但实际零结果 | 只播后台真进度，否则退化为范围型 |
| 用"哔"声/加载音 | 技术暴露，破坏沉浸 | 只用人声 |
| 承诺"马上就好" | 超时即失信 | 改为"这个要查一下" |

### 8.2 风险与对策

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 垫词与答案冲突 | 冲突率 > 0 | 规则比对 + 降级通用句 |
| 预测等待不准 | 空洞率高 | EWMA 重估 + 退保守档 |
| 模板同质化 | 重复率高、用户复问 | 扩变体池 + 按场景分池 |
| 生成越界 | 越界率 > 2% | 负例增训 + 后置过滤 |
| 打断时垫词未停 | 打断后仍有音频 | 走 cancel 树，L3 停止生成 |
