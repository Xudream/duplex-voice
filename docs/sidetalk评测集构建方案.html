1. 目的与边界

1.1 这份文档解决什么

《拒识sideTalk设计文档》定义了"要判什么"（S1–S4 归属问题）和"判到什么程度"（分场景目标），但没有回答三个工程问题：

问题本文给出的答案
用哪些数据、各多少条？§2 资源清单 + §3 公开集映射 + §4 自建集配额
模型之间怎么比才可信？§6 统计口径（CI、McNemar、工作点曲线）
谁来跑、跑出什么？§5 harness 规格 + §8 排期与交付物

1.2 两把尺子的分工

尺子数据用途决策权
尺子 1（公开集）HumDial-FDBench、CoDeTT、WearVox、ChorusDuplex淘汰赛：把 8–10 个候选模型筛到 2 个只做淘汰，不做最终定选
尺子 2（自建集）音箱远场 + 手机近场实测定选 + 验收：中文真实声学、S1 主场景最终结论以尺子 2 为准

理由：公开集覆盖面广但形态不对（英文/眼镜/合成），自建集贴产品但规模小、拿不到业界坐标。两者互补，不可互相替代。

1.3 三条口径纪律

  1. dev/test 隔离：任何 prompt、阈值、规则调参只能碰 dev；test 只在最终表报一次，触碰即该版本 test 作废。
  2. 只报分布不报单点：所有指标给点值 + 95% 置信区间；差异小于 CI 宽度时不写"优于"。
  3. 一票否决不参与加权：误执行（应静默却触发工具）恒为 0，不做加权平均，出现即淘汰。

2.2 合计规模与统计功效

用途样本量指标假设95% CI 半宽能分辨的最小模型差异

HumDial 拒识 test（对外坐标）2,000（SDO 仅 200 / TPS 600）p=0.90SDO ±4.2 pt / TPS ±2.4 ptSDO 上 ~8 pt
WearVox（眼镜参考）1,082p=0.90±1.8 pt~4 pt
ChorusDuplex（CI 冒烟）134p=0.90±5.1 pt只能抓大退化

> 结论：HumDial 的 SDO 子集（200 条）不能用来选型——两个模型差 4 个点在统计上就是噪声。它只做对外坐标与回归；选型分辨器必须是 CoDeTT + 自建集。

2.3 一个必须先知道的事实：SDO 没有训练数据

3.3 五个已知的坑

#坑后果处理
1HumDial test 的 SDO 只有 200 条无法区分 <4pt 的模型差异只做坐标；选型靠 CoDeTT + 自建
2SDO/TPS 训练样本为 0/120不能拿公开集训练 S1 判别器自建集承担训练；公开集只评测
3WearVox 的 1,082 里有 500 条是从 tool-calling 复制的正例正负比例失真、同一音频多任务复用报数时分开统计；不要把这 500 当独立正例做 FRR 主结论
4ChorusDuplex 是 TTS 合成、只有 134 条 side_talk只能做链路冒烟，不能当验收CI 必跑、不作为定选依据
5CoDeTT 子集条数未在 README 给出（仅给 18,000 总量 / 14 类）±1.3pt 的精度声明可能不成立解压后核对；若为 1,000 条则改为 ±1.8pt、"可分辨 ~4pt"

3.4 输入构造三要素（跨集统一，缺一条结论就不可比）

要素规格各集取值
音频按各集原始声道布局，48kHz 或原采样率，不做重采样以外的处理HumDial 双通道；Chorus 立体声 L=非助手/R=助手；WearVox 单通道版与 mc 版各跑一遍
系统态idle / speaking 二值，显式给定HumDial、CoDeTT 由标注给；Chorus 由 trigger 推
多轮历史最近 5 轮转写，纯文本各集自带标注；不足补空；不得含 gold 的 addressee 标签

3.5 判分规则


输入：模型输出 JSON {"action":..., "confidence":..., "reason":...}
规则优先级：
1. 解析失败 / 动作不在允许集合 → 记 invalid，单独计数（>1% 视为该模型不可用于产品）
2. action = silent | silent_record → 判"静默"
3. action = clarify → 记"非静默"，单列，不计入拒识率分子、不计入 FAR
4. action = respond | ack | wait → 判"响应"（应静默样本即算误响应；S0 样本算正确）
5. 应静默样本上 action 触发工具调用 → 记"误执行"（一票否决）

公开集的 gold 只有"该静默 / 该响应 + 理由类别"，因此：

  • CoDeTT 四动作映射：Dismiss→silent、Takeover→respond、Stop&Listen/Maintain→仅回归（语义 VAD 域）
  • clarify 在 CoDeTT 上不计入 4 动作 ACC，单列 clarify 率

3.6 各集门槛与 sanity check

集必须先复现的基线允许偏差复现失败怎么办
HumDial官方 Baseline 拒识 35.2、冠军 72.2±3 pt判 harness bug（时序对齐/RS 计算），修完再跑
WearVox两段式基线 85.6%（单通道）±3 pt检查声道选择与重采样
CoDeTT仓库给出/可复现的四动作 baseline±3 pt检查系统态与 5 轮历史拼装
ChorusDuplex无官方基线—用规则基线（全 respond）与全 silent 定位下限/上限

4.3 采集 SOP

  1. 演员照脚本演（对齐 HumDial 的"LLM 脚本 + 演员表演"），打断/重叠发生在语义接缝（迟疑、换气）而非随机时间戳
  2. side-talk 脚本不得含唤醒词；对抗子集单独成轨，故意含"帮我/小X"但交流对象明确是旁人
  3. 每段 10–30 s，同步记录：SNR、混响估计（RT60）、DoA 真值、距离真值、设备型号与摆位
  4. 同一场景至少 3 个 take，事后按自然度挑选，未选中 take 保留为"边缘样本"备查
  5. 现场即校验：波形不削波、双通道无串音、标注文件与音频文件名一一对应

4.4 标注 schema 与一致性

层级字段
段级speaker_role（primary/other/media）、directed_to（assistant/companion/none）、gold_action（respond/ack/wait/clarify/silent/silent_record）、scene_tags[]、is_adversarial
轮级词级时间戳、转写、意图标签、与上一系统轮的衔接类型（答句/打断/无关/附和）
  • 双人独立标注 + 第三人仲裁；Cohen's κ ≥ 0.8 才入库
  • 每版本抽 10% 复标，κ 掉到 0.7 以下整批返工
  • 标注指引单独成文（含 20 条边界样例），随版本号管理

4.5 切分与防泄漏

措施做法
说话人隔离train/dev/test 三集说话人不重叠（按人切，不按段切）
场景隔离同一房间/同一噪声组合不出现在两个 split 的同一场景里
去重音频指纹（chromaprint）查重，同源脚本的不同 take 不跨 split
防泄漏脚本文本、录音日期、噪声源名不出现在 prompt 中；评估时不向模型透露"这是测试"
训练用途只有 train 可用于训练 L2 判别器；test 只评不训

4.6 成本与排期【估算】

项数量说明
有效音频3,000 × 20 s ≈ 16.7 h拍摄比按 1:3，现场约 50 h
录音6 个工作日2 演员 + 1 录音师 + 2 种设备
标注约 750 人时（≈94 人日）3,000 段 × 双标 + 仲裁

5.1 目录结构

 "audio":"data/humdial/test/xxx.wav","channels":2,
 "system_state":"speaking","history":[{"role":"user","text":"..."}],

5.3 predictions 字段


{"id":"humdial-test-SDO-000123","model":"qwen3-0.6b-npu","run":"2026-11-03T10:00Z",
 "action":"silent","confidence":0.87,"reason":"...","latency_ms":42,
 "raw":"<原始输出，便于回溯>"}

5.4 解析与容错

  • 动作不在白名单 → invalid（单独计数，>1% 该模型直接出局）
  • 缺 confidence → 按 1.0 计，但记 warn_missing_conf
  • 分类模型（非生成式）输出概率向量 → 取 argmax，confidence 取该概率

5.5 score.py 输出


reports/<model>__<manifest>.md
  ├─ 分场景表：S1/S2/S3/S4 拒识率（点值 + 95%CI）
  ├─ 汇总：FAR_w、FRR、误执行、clarify 率、invalid 率
  ├─ 延迟：P50/P90（决策延迟、响应首延迟）
  └─ 错误归因：ACC 错 / 应静默却 respond / 蒙对但 SMR 命中

6. 指标与统计

6.1 指标定义

指标公式备注
分场景拒识率Rej_s = 正确静默数_s / 应静默数_s按 S1–S4 分别出
加权误响应率FAR_w = Σ w_s × (1 − Rej_s)w 按产品流量占比（起始建议 S1 0.40 / S2 0.15 / S3 0.25 / S4 0.20）；不设独立常数门槛
漏响应率FRR = S0 被误吞数 / S0 总数承诺 ≤3%，内部目标 2% 待 S0≥3,000
误执行计数一票否决，报 0/N 与 95% 上界 ≤3/N
clarify 率clarify 次数 / 总样本监控 ≤2%，不计入 FAR
决策延迟语音结束 → silent 落定P50/P90，窗 ≤500 ms
响应首延迟增量含裁判 vs 不含裁判P90 增量 ≤100 ms

6.2 工作点而不是单点

对每个模型扫 confidence 阈值 0.05–0.95（步长 0.05），报三条：

  1. 固定 FAR_w = 5% 处的 FRR
  2. 固定 FRR = 3% 处的 FAR_w
  3. FAR–FRR 曲线的 AUC（AUC 越大越好，可用梯形法）

只报"拒识率 92%"是无意义的——不同阈值下可以差 15 个点。

6.3 置信区间与显著性

场景方法
单模型单指标Wilson 区间（不用正态近似，p 接近 0/1 时更稳）
两模型同批样本McNemar 检验（配对，只看不一致样本）
AUC/曲线差异Bootstrap 1,000 次，报差值的 95%CI
多模型比较Holm 校正，避免多重比较假阳性

6.4 报数纪律

  • 差异 < CI 宽度 → 写"不可区分"，不写"略优"
  • 每次结果必须带：模型版本、prompt 版本、manifest hash、运行时间
  • 同一张表里不允许混用不同 split 的数据

7. 模型选型打分卡

7.1 硬淘汰线（任一触发即出局）

条件阈值
误执行> 0
invalid 输出率> 1%
S1 拒识率< 80%
决策延迟 P90> 800 ms
部署约束需出境且无替代方案

7.2 加权打分（通过硬淘汰后）

维度权重计分方式
S1 拒识率（CoDeTT + 自建 dev）30线性映射，80%→0 分，95%→满分
FAR_w @ FRR≤3%25越低越好，5%→满分，15%→0 分
误执行余量150 次满分，出现即淘汰（本项用于排名区分）
决策延迟 P9010≤300ms 满分，800ms→0 分
可部署性（端侧/私有化）10端侧满分，私有化 7，仅 API 3
成本（每千次决策）10≤¥1 满分，¥10→0 分

7.3 两条跑道与对照

跑道输入候选作用
A 文本裁判转写 + 系统态 + 5 轮历史Qwen3-0.6B/1.7B/4B、Qwen3.5-4B/9B、DeepSeek-V4-Flash、Jev（L3 快分支）、规则+BERT 分类器（必跑基线）主选型跑道
B 端到端原始音频Qwen-Audio-3.1-Realtime、Gander、Moshi给出"模型自带拒识"上界

A 跑道必须跑两版：gold 转写 与 真实 ASR 转写。两版差值 = ASR 误差传导，这是选型结论里最有价值的一列（决定"值不值得为 ASR 升级付费"）。

10.3 指标公式汇总


Rej_s      = 正确静默_s / 应静默_s
FAR_w      = Σ_s w_s (1 − Rej_s)
FRR        = 误吞数_S0 / 总数_S0
clarify率  = clarify数 / 总样本
决策延迟    = t(decision) − t(speech_end)          # P50/P90
CI 半宽     = z·√(p(1−p)/n),  z=1.96
最小可分辨差 ≈ 2 × CI 半宽
