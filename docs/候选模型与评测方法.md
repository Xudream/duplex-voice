## 1. 候选池：两条跑道

### 1.1 跑道 A：文本裁判（主跑道）

输入 = 转写 + 系统态 + 5 轮历史；输出 = 动作 JSON。这是"外挂裁判"路线的最小验证形态。

| # | 候选 | 形态 | 部署 | 成本口径【估算】 | 为什么进候选 | 备注 |
|---|---|---|---|---|---|---|
| A0 | **规则 + 字符 n-gram/BERT 分类器** | 判据可解释 | 端侧/CPU | 0 | **必跑基线**：不跑它不知道 LLM 到底加了多少分 | 用 train 集训，测试集不碰 |
| A1 | Qwen3-0.6B | 开源 LLM | 端侧 NPU 可行 | 电费 | 端侧 L2 的最低成本档 | 指令遵循弱，看它能否守住协议 |
| A2 | Qwen3-1.7B | 开源 LLM | 端侧/单卡 | 电费 | 端侧 L2 主力候选 | 需实测 NPU 延迟（10–50ms 存疑） |
| A3 | Qwen3-4B | 开源 LLM | 单卡 A10/A100 | 电费 | 精度与端侧折中 | 量化后显存 ~3GB |
| A4 | Qwen3.5-4B | 开源 LLM | 单卡 | 电费 | 新代际，中文更强 | 需核对许可与量化可用性 |
| A5 | Qwen3.5-9B | 开源 LLM | 24G 卡 | 电费 | 强基线（也是 L3 小脑候选） | 延迟偏高，适合做 L3 复判 |
| A6 | DeepSeek-V4-Flash | 托管 API | 云 | 按 token | 低价快模型 | 需确认是否支持 JSON 约束 |
| A7 | DeepSeek-V4-Pro | 托管 API | 云 | 按 token | 强推理，做 L3 强分支 | 不适合每轮调用 |
| A8 | GLM / 豆包（各取一档） | 托管 API | 云 | 按 token | 横向对照，避免单一供应商偏差 | 用同一 prompt |
| A9 | **Jev（TypeSafe System One）** | 有界决策模型 | 托管 API（无权重） | $0.042/M input | 决策型模型的代表：0% 类型错误、带校准置信度 | 不能端侧；需评估数据出境 |

> 跑道 A 里 **A0 是必跑项**，A1–A9 建议全跑（成本 < ¥100），因为裁判模型的差异往往只有 2–4pt，样本量足够才能分辨。

### 1.2 跑道 B：端到端语音模型（对照组）

输入 = 原始音频；输出 = 响应/静默。用来量化"模型自带拒识"的上界，以及外挂路线还差多少。

| # | 候选 | 形态 | 可私有化 | 拒识相关公开证据 | 备注 |
|---|---|---|---|---|---|
| B1 | Qwen-Audio-3.1-Realtime | 云端实时 | 否 | FD-Bench v1.5 背景语音响应 73%→13% | 官方文档明确支持 `smart_turn` + 说话人增强 |
| B2 | 豆包 Seeduplex 3.0 | 云端实时 | 否 | 端到端全双工；官方文档 | 需确认是否开放"拒识/静默"显式控制 |
| B3 | 腾讯 Gander | 开源（Apache-2.0） | 是 | FD-Bench v3 接管 100% / 抢话 8.0% | 自部署成本高（≈9B），适合做上界参照 |
| B4 | GLM-Realtime | 云端 | 否 | 音视频通话，2 分钟记忆 | 价格 0.18 元/分钟（音频） |
| B5 | Step-Audio 2 mini | 开源 | 是 | URO Bench 开源最高（自报） | 轻量，适合跑通链路 |
| B6 | Moshi | 开源 | 是 | 全双工可打断 | 英文为主，做参照 |

## 2. 评测方法（可直接执行）

### 2.1 四组实验矩阵

| 组 | 跑道 | 输入 | 目的 |
|---|---|---|---|
| E1 | A | **gold 转写** | 裁判能力上限（排除 ASR 干扰） |
| E2 | A | **真实 ASR 转写** | 真实链路能力（与产品一致） |
| E3 | B | 原始音频 | 端到端上界 |
| E4 | A | gold 转写 + 打乱历史 | 消融：历史到底有没有用 |

E1 与 E2 的差值 = **ASR 误差传导**，这是决定"要不要为 ASR 升级付费"的唯一硬证据。

### 2.2 统一动作协议

```json
{"action":"respond|ack|wait|clarify|silent|silent_record","confidence":0.0,"reason":"≤20 字"}
```

解析规则（`llm_judge.py` 已实现）：
1. 非 JSON / 动作越界 → `invalid`（单独计数，>1% 该模型出局）
2. `clarify` 单列，不计入拒识率分子、不计入 FAR
3. `silent_record` 与 `silent` 在指标上等价

### 2.3 三阶段执行

| 阶段 | 样本 | 目的 | 通过条件 |
|---|---|---|---|
| 冒烟 | 每集 100 条（分层抽） | 验证协议、暴露 prompt 问题 | invalid <1%、无 429 |
| 全量 | 2,595 条（音频就位部分） | 出正式表 | 全部模型同批样本 |
| 复跑 | 全量的 10% | 稳定性（temperature=0 应 100% 一致） | 不一致率 <1%，否则查采样 |

### 2.4 指标与统计

| 指标 | 口径 |
|---|---|
| 分场景拒识率 | 按 S1/S2/S3 分别出（S4 暂无样本） |
| FAR_w | Σ w_s(1−Rej_s)，w = S1 0.40 / S2 0.15 / S3 0.25 / S4 0.20（缺项自动归一） |
| FRR | S0 被置静默的比例（S0_guest 单列，不计入） |
| 误执行 | 一票否决 |
| 决策延迟 | P50/P90（从提交到拿到动作） |
| 工作点 | 扫 confidence 0.05–0.95，报「FAR_w=5% 处的 FRR」与「FRR=3% 处的 FAR_w」 |
| 显著性 | Wilson CI；同批样本两模型用 McNemar；AUC 差用 bootstrap 1000 次；多模型 Holm 校正 |

**报数纪律**：差异小于 CI 宽度就写"不可区分"。当前样本量下（见 §3）可分辨的最小差异约 2–4pt。

### 2.5 淘汰与提名

硬淘汰（任一触发）：误执行 >0、invalid >1%、S1 拒识 <80%、P90 延迟 >800ms、无法私有化。

通过后按 §1.3 加权排序，取前 2 名进入尺子2（自建集 + 真机）。

### 2.6 成本与时间【估算】

| 项 | 数量 | 估算 |
|---|---|---|
| 样本 × 模型 | 2,595 × 9（A 跑道） | 约 23,400 次调用 |
| 单次 token | ~400 in / 40 out | 约 10M input tokens |
| Jev 成本 | $0.042/M | < $1 |
| LLM API 成本（均价 ¥2/M） | — | < ¥50 |
| 本地模型（A1–A5） | 单卡 | 约 6–8 机时 |
| 人工 | 1 人 | 2 天（含跑批与出表） |

### 2.7 复现命令

```bash
cd ~/repos/projects/duplex-voice/tools/ruler1
DATA=~/.hermes/workspace/ruler1/data
# 生成清单（含 audio_ok 标记）
python3 build_manifests.py --dataset all --data $DATA --out manifests

# 冒烟：先跑 100 条
python3 llm_judge.py --manifest manifests/chorus.jsonl --backend openai_compat \
  --base-url https://dashscope.aliyuncs.com/compatible-mode/v1 --model qwen-plus \
  --limit 100 --out predictions/qwen-plus__chorus__smoke.jsonl
python3 score.py --manifest manifests/chorus.jsonl \
  --pred predictions/qwen-plus__chorus__smoke.jsonl --only-predicted --sweep

# 全量：同一条命令去掉 --limit；换模型只改 --model / --base-url
```
