L3 模型选型评测方法：多评测集组合与决策规则

版本 v1.0　·　2026-10-25　·　适用对象：L3 小脑（Talker LLM）选型与版本迭代验收

与《四层架构方案》§4.6 配套：那份文档定义了"要测什么"，本文定义"用哪些集、怎么合成一个结论"。

口径约定：【官方】取自论文或官方页；【实测】为项目内真实调用；【估算】为工程推算，须实测替换。

1. 适用范围与结论

1.1 适用场景

场景是否适用说明
首次选型（9B / 4B / 云端对照）适用全套流程
换量化版本（BF16 → AWQ 4bit）适用只需 A/C/E 三轴
LoRA 迭代验收适用需固定基座与量化，只变权重
换模型家族（Qwen → 其他）适用需重跑全套，公开集权重可上调
端到端系统评测不适用那是 L1–L4 联调，另立基准

1.2 三条结论

  • 没有任何单一评测集能选 L3：L3 的任务是"给定素材、按约束说人话"，公开榜单考的是问答正确性与写作质量，形态错配。
  • 多评测集组合成立，但要按"轴"组合，不能按"数量"堆：同一轴放三个集会隐式把该轴权重乘三，最后选出"单项极强、整体失衡"的模型。
  • 公开集只能证明"不行"，自建集才能证明"行"：公开集提供横向可比性，自建集提供与线上分布贴合度，缺一不可。

    2. 为什么不能只用单一评测集

    2.1 任务形态错配

    维度L3 的实际任务公开榜单考的
    输入指令 + 已给定的素材（结论句、字段）开放问题，模型自己找事实
    输出8–30 字口语，首句 ≤15 字长文、代码、推理链
    评判数字原样、不评价、不重复、不越界内容正确性、写作质量
    语言中文口语（语气词、省略、断句）以英文为主
    精度AWQ 4bit 部署版BF16 原版

    五个维度全部错配，所以"榜单第一"对 L3 选型几乎无信息量。

    2.2 同轴重复计权的陷阱

    假设工具轴放了 BFCL、τ²-bench、自建工具集三个集，转述轴只有一个自建集：

    名义权重：工具 30%  转述 30%
实际权重：工具 (30/2 + 30/2 + 30/2) 被放大，转述被相对稀释
结果：选出工具最强、转述最差的模型，而转述才是用户感知最强的能力

    规则：每个轴最多两个集（1 个公开 + 1 个自建），轴内先合成再参与轴间加权。

    2.3 公开集与自建集的分工

    角色谁承担能回答的问题不能回答的问题
    淘汰赛公开集这个模型是不是明显不行它在我们场景里行不行
    排位赛自建集谁更适合我们的分布它能不能扛更大的任务
    诊断错误归因类集错在选工具、漏参还是格式错了会不会被用户感知

    3. 评测集组合（suite）

    3.1 六轴十四集总表

    轴评测集覆盖什么角色类型判分
    A 工具调用BFCL v4（simple / multiple / parallel / 多轮 / agentic 分层）函数选择与参数填写粗筛及格线公开自动
    A 工具调用PluginEval函数调用错误归因（选错 / 漏参 / 格式）诊断，不计分公开自动
    A 工具调用τ²-bench（retail / airline / telecom）多轮工具编排与双控仅多轮场景公开自动
    A 工具调用自建工具集（中文口语）真实说法 → 工具与参数主判据自建自动
    B 约束遵循IFEval25 类可验证约束（字数/格式/禁用词）格式与长度公开自动
    B 约束遵循自建口语约束集首句 ≤15 字、禁 markdown、禁列表主判据自建自动
    C 忠实性FActScore 思路原子事实可归因辅助公开半自动
    C 忠实性HaluEval 中文子集幻觉识别辅助公开judge
    C 忠实性自建数字/专名保真集数字与专名原样搬运硬门槛自建自动
    D 口语质量人工成对比较自然度、口语感、节奏主判据自建人工
    D 口语质量LLM-judge rubric与人工校准后的批量打分辅助自建judge
    E 时延首 token / 整句 P50·P95（单并发）实时性硬门槛实测自动
    E 时延并发 1/4/8 的 P95 + OOM 边界容量硬门槛实测自动
    F 稳定性同输入 5 次采样一致率、8k/32k 退化抖动与长上下文辅助实测自动

    公开集出处：BFCL v4 见 Gorilla 官方榜；IFEval 见 arXiv:2311.07911；τ²-bench 见 ICML 2026；

    PluginEval 见 arXiv:2608.08700；FActScore / HaluEval 为公开可用基准（评分思路借用，中文需重写 rubric）。

    3.2 每轴的选择依据

    轴为什么必须有为什么只用这几个
    A 工具L3 的本地闭环能力靠它BFCL 覆盖标准切面，PluginEval 负责诊断，自建集负责真实中文说法；τ²-bench 只在需要多轮时启用
    B 约束音色与可听性依赖长度与格式IFEval 是唯一成熟的可验证约束基准；口语长度约束它不覆盖，只能自建
    C 忠实性转述改数字是最高危错误数字/专名可用字符串精确判，最可靠；FActScore/HaluEval 只做交叉验证
    D 口语公开集完全没有覆盖只能用人工成对比较；judge 仅用于批量初筛
    E 时延硬约束，榜单不给必须自己压测，且要测量化版本
    F 稳定抖动会放大成"时好时坏"同输入重复采样成本低

    3.3 公开集的已知局限

    局限表现应对
    语言错配以英文为主，中文口语覆盖薄中文场景提高自建集权重（70% : 30%）
    精度错配榜单多为 BF16所有候选按部署量化（AWQ 4bit）重跑
    提示错配榜单用自己的 prompt 与 template统一 prompt/template/约束解码，否则不可比
    数据污染部分题可能进过训练集私有改写 held-out（见 §7.1）
    难度错配榜单题目超出/低于 L3 实际分布只做淘汰，不做排位

    3.4 自建集的必要覆盖

    覆盖项为什么必须自建最小条数
    承接语不越界任何公开集都没有"只许说状态"的约束40
    数字/专名保真需要精确比对而非语义相似60
    中文口语转述口语省略、语气词、断句60
    空结果与超时真实链路的必现分支20
    近邻易混（同一问法不同对象）检验槽位与指代30
    素材不足（必须说不知道）抑制编造20

    4. 自建评测集设计

    4.1 素材来源与分层抽样

    优先级来源占比建议说明
    1真实语音转写（脱敏）50%分布最真，含口音与断句
    2后台真实输出（结论句 + 字段）30%转述题的天然来源
    3人工构造边界题20%空结果、超时、素材不足、近邻易混

    分层配比（标准档 300 条）：

    分层120 条（最小档）300 条（标准档）500 条（完整档）
    承接语 fill2460100
    结果转述 narrate3690150
    进度转述 progress123050
    直答措辞 answer2460100
    工具调用 tool184880
    负例（不该说/素材不足）61220

    4.2 记录结构与"评行为不评字面"

    {
  "id": "narrate-012",
  "axis": ["C", "B"],
  "beat": "narrate",
  "user_utterance": "明天郑州天气怎么样",
  "material": {"conclusion": "明天郑州有雨，12 到 18 度", "facts": ["降水概率 80%"]},
  "expect": {
    "behavior": "narrate",
    "must_include": ["郑州", "12", "18", "80%"],
    "must_not": ["评价词", "素材外事实"],
    "max_first_sentence_chars": 15
  },
  "meta": {"source": "asr_log", "split": "heldout", "version": "v1"}
}

    三条硬规定：

  • 禁止写"期望文本"。写了就退化成文本相似度，模型换个说法就被判错。
  • must_include 只放可精确匹配的原子（数字、专名、单位）。
  • must_not 用类别而非穷举：评价词、素材外事实、承诺语。

    • 4.3 五类判定方式

    判定方式用于可靠性成本
    精确匹配（子串/正则）数字、专名、单位高极低
    结构比对工具 id + 参数键值高低
    规则计数字符数、标点、markdown 标记高极低
    LLM-judge（校准后）越界、加评价、口语自然度中（κ≈0.5）中
    人工成对比较口语质量排序高高

    原则：能用精确匹配的，绝不用 judge。

    4.4 数据量与统计下限

    每类样本量下限：

    n ≥ z² · p(1−p) / e²        z=1.96, p=0.9
  e=±10% → 35（仅冒烟）
  e=±5%  → 138
  e=±3%  → 384

    含义：单层少于 35 条的分数不要写进结论；想区分两个模型 3 个点的差距，单层需要 384 条。

    所以"最小档 120 条"只能做淘汰，不能做精细排位。

    4.5 质检与版本管理

    检查方法门槛
    素材可追溯每条 expect 的原子必须来自 material100%
    配比正确脚本统计分层条数与 §4.1 一致
    去重句级 simhash重复 <3%
    与训练集隔离n-gram 重叠检查13-gram 重叠 = 0
    版本冻结version 字段 + 提交后冻结评测中途不得改题

    5. 打分与决策

    5.1 硬门槛（不满足直接淘汰）

    门槛阈值依据
    数字/专名保真= 100%转述改数字是最严重的可信度事故
    自建工具参数准确率≥ 97%与《四层架构方案》§4.6 一致
    越权工具调用= 0安全底线
    素材外编造= 0同底线
    首 token（单并发）≤ 350ms承接语覆盖窗口
    24G + AWQ 并发≥ 3三路通话
    量化掉点（BF16 → AWQ）≤ 3 分部署形态必须可比

    5.2 归一化

    各集分数尺度不同（BFCL 是 0–100 准确率，人工比较是胜率），禁止直接加权。

    z_i = (x_i − μ_group) / σ_group        // 候选群体内标准化
或
m_i = (x_i − min) / (max − min)        // 候选仅 2–3 个时用 min-max

    候选少于 3 个时优先用 min-max（z-score 在 n=2 时退化为 ±1，信息量低）。

    5.3 轴内合成与轴间加权

    轴分 = 0.7 × 自建集z + 0.3 × 公开集z
总分 = 0.30×C保真 + 0.25×A工具 + 0.20×D口语 + 0.10×B约束 + 0.15×E时延

    例外：D（口语）没有公开集，按 1.0 人工比较计；E（时延）是实测值，直接进 z 计算，不做自建/公开合成。

    权重理由：

    轴权重理由
    C 保真30%错一个数字，用户信任直接受损
    A 工具25%决定"能不能闭环"
    D 口语20%决定"像不像人"，用户感知最强
    B 约束10%影响可听性，但可由模板兜底
    E 时延15%硬约束，但已设门槛，此处只比余量

    5.4 决策规则

    条件决策
    任一门槛不过淘汰
    加权分差 < 5 分选小模型（4B）——省资源、首字更快
    加权分差 ≥ 5 分选大模型（9B）
    分差在 4–6 分之间看短板：转述输不能接受；工具输可以接受（可加约束解码补）

    5.5 算例（9B vs 4B，示意数据）

    轴9B4B9B z4B z权重9B 贡献4B 贡献
    C 保真100%98.3%+1−130%+0.30−0.30
    A 工具98.1%94.2%+1−125%+0.25−0.25
    D 口语胜率 62%38%+1−120%+0.20−0.20
    B 约束96%93%+1−110%+0.10−0.10
    E 时延260ms180ms−1+115%−0.15+0.15
    合计————100%+0.70−0.70

    （示例只示意算法，真实 z 值须按候选群体计算。）

    结论：9B 总分领先 1.4 个标准差，且 4B 在保真轴上不达标（98.3% < 100%），先被门槛淘汰。

    6. 冲突裁决与一致性检验

    6.1 同轴多集的一致性

    Kendall τ（或 Spearman ρ）≥ 0.6  → 该轴结论可信
τ < 0.6                          → 该轴存在污染或难度错配

    处置：换 held-out 子集重跑；仍 <0.6 则弃用其中一个集，并在报告里写明原因。

    6.2 跨轴冲突

    冲突形态裁决
    大模型工具强、小模型转述强转述优先（用户感知最强，且难以用工程手段补）
    公开集说 A 好、自建集说 B 好以自建集为准
    时延与质量冲突先看门槛，再看"承接语能否覆盖"

    6.3 公开集的作用边界

    公开集可以用来：

  • 淘汰明显不达标的候选
  • 与外部（同事、厂商、竞品）沟通时提供共同语言
  • 交叉验证自建集结论是否离谱

    • 不能用来：

  • 单独决定选型
  • 证明"可以上线"（它不覆盖你的分布）

    • 7. 防污染与对齐

    7.1 私有改写 held-out

    每个公开集抽 20% 做三件事，只报改写后的分数：

    改写例子目的
    同义改写"把灯打开" → "帮我开一下灯"破坏 n-gram 记忆
    数值替换城市、时间、金额换掉破坏答案记忆
    选项打乱多选项顺序随机破坏位置偏好

    判读：改写后掉分 >10 分 → 疑似污染，该集降权或弃用。

    7.2 执行一致性（不做这步，多集全白跑）

    项必须统一
    prompt / system同一份字符串
    chat template与基座一致
    约束解码同开或同关（工具分支必须开）
    量化全部 AWQ 4bit
    采样参数temperature / top_p / max_tokens 固定
    并发压测报告注明并发数

    7.3 judge 校准

    2026 年两项系统性研究（arXiv:2606.19544 评测 21 个 judge；arXiv:2606.13685）指向同一结论：

    主观任务上跨 judge 一致性只有 κ≈0.51，接近随机。因此：

    规则说明
    judge 与被测模型不同源同源会系统性偏高
    人工复核 20%逐条比对 judge 与人的判定
    一致率 <0.7换 judge 或把主观项拆成可判子问题（如"是否出现素材外数字"）
    judge 只做初筛最终分以人工复核后的为准

    8. 执行流程与预算

    8.1 三档预算

    档位工期包含适用
    最小1 天BFCL 子集 + 自建 120 条 + 时延淘汰明显不行的候选
    标准3–5 天BFCL v4 + IFEval + 自建 300 条 + judge 校准 + 并发与量化对比正式选型（推荐）
    完整2 周+ τ²-bench + FActScore 改写 + 影子 3 天立项评审前

    8.2 两周标准流程

    日任务产物
    D1–D2造 300 条（真实转写 + 后台输出 + 构造边界）eval/selfbuilt_v1.jsonl
    D3跑候选（9B AWQ / 4B AWQ / 一个云端对照）每候选一份 per-item CSV
    D4跑 BFCL v4 子集 + IFEval公开集分数表
    D5时延实测：首 token、整句、并发 1/4/8latency.csv
    D6–D7judge 初筛 + 人工复核 20%，算一致率judge_calibration.md
    D8汇总打分（z/min-max + 权重 + 门槛）decision.md
    D9–D10影子模式旁路跑 3 天（只看不播）shadow_report.md

    8.3 产物清单（harness 建成后）

    产物说明
    eval/suite.yaml轴、集、权重、门槛的唯一定义
    eval/selfbuilt_v1.jsonl自建集（冻结版本）
    eval/runner.py统一跑批（同 prompt / 同量化）

    9. 风险与反模式

    9.1 五个反模式

    反模式后果纠正
    拿榜单排名直接拍板选到"榜单强、场景弱"的模型榜单只做淘汰
    同一轴堆三个集该轴权重被隐式放大每轴 ≤2 集，轴内合成
    用期望文本做标注退化成相似度，换说法就判错评行为不评字面
    judge 一把梭κ≈0.5，结论不可复现客观项自动判 + 主观项人审 20%
    用 BF16 分数代表部署效果量化掉点 2–5 分被忽略全部按 AWQ 4bit 重跑

    9.2 风险与对策

    风险触发信号对策
    评测集被训练污染改写后掉分 >10弃用该集或只用 held-out
    自建集分布偏线上影子与离线差 >10%每季度用真实日志补题
    标注者口径不一双人标注 κ <0.6先写标注手册再标注
    结论不可复现两次跑分差 >3固定随机种子与采样参数，记录版本
    过度优化评测集线下涨、线上不涨影子模式为准，离线只做准入
