# L3 模型选型评测方法：多评测集组合与决策规则

> 版本 v1.0　·　2026-10-25　·　适用对象：L3 小脑（Talker LLM）选型与版本迭代验收
> 与《四层架构方案》§4.6 配套：那份文档定义了"要测什么"，本文定义"用哪些集、怎么合成一个结论"。
> 口径约定：【官方】取自论文或官方页；【实测】为项目内真实调用；【估算】为工程推算，须实测替换。

## 1. 适用范围与结论

### 1.1 适用场景

| 场景 | 是否适用 | 说明 |
|---|---|---|
| 首次选型（9B / 4B / 云端对照） | 适用 | 全套流程 |
| 换量化版本（BF16 → AWQ 4bit） | 适用 | 只需 A/C/E 三轴 |
| LoRA 迭代验收 | 适用 | 需固定基座与量化，只变权重 |
| 换模型家族（Qwen → 其他） | 适用 | 需重跑全套，公开集权重可上调 |
| 端到端系统评测 | 不适用 | 那是 L1–L4 联调，另立基准 |

### 1.2 三条结论

1. **没有任何单一评测集能选 L3**：L3 的任务是"给定素材、按约束说人话"，公开榜单考的是问答正确性与写作质量，形态错配。
2. **多评测集组合成立，但要按"轴"组合，不能按"数量"堆**：同一轴放三个集会隐式把该轴权重乘三，最后选出"单项极强、整体失衡"的模型。
3. **公开集只能证明"不行"，自建集才能证明"行"**：公开集提供横向可比性，自建集提供与线上分布贴合度，缺一不可。

### 1.3 与四层架构方案的关系

| 文档 | 定义 | 位置 |
|---|---|---|
| 四层架构方案 §4.6 | 指标清单与目标值 | `docs/四层架构方案.md` |

## 2. 为什么不能只用单一评测集

### 2.1 任务形态错配

| 维度 | L3 的实际任务 | 公开榜单考的 |
|---|---|---|
| 输入 | 指令 + 已给定的素材（结论句、字段） | 开放问题，模型自己找事实 |
| 输出 | 8–30 字口语，首句 ≤15 字 | 长文、代码、推理链 |
| 评判 | 数字原样、不评价、不重复、不越界 | 内容正确性、写作质量 |
| 语言 | 中文口语（语气词、省略、断句） | 以英文为主 |
| 精度 | **AWQ 4bit 部署版** | BF16 原版 |

五个维度全部错配，所以"榜单第一"对 L3 选型几乎无信息量。

### 2.2 同轴重复计权的陷阱

假设工具轴放了 BFCL、τ²-bench、自建工具集三个集，转述轴只有一个自建集：

```
名义权重：工具 30%  转述 30%
实际权重：工具 (30/2 + 30/2 + 30/2) 被放大，转述被相对稀释
结果：选出工具最强、转述最差的模型，而转述才是用户感知最强的能力
```

规则：**每个轴最多两个集（1 个公开 + 1 个自建），轴内先合成再参与轴间加权。**

### 2.3 公开集与自建集的分工

| 角色 | 谁承担 | 能回答的问题 | 不能回答的问题 |
|---|---|---|---|
| 淘汰赛 | 公开集 | 这个模型是不是明显不行 | 它在我们场景里行不行 |
| 排位赛 | 自建集 | 谁更适合我们的分布 | 它能不能扛更大的任务 |
| 诊断 | 错误归因类集 | 错在选工具、漏参还是格式 | 错了会不会被用户感知 |

## 3. 评测集组合（suite）

### 3.1 六轴十四集总表

| 轴 | 评测集 | 覆盖什么 | 角色 | 类型 | 判分 |
|---|---|---|---|---|---|
| A 工具调用 | BFCL v4（simple / multiple / parallel / 多轮 / agentic 分层） | 函数选择与参数填写 | 粗筛及格线 | 公开 | 自动 |
| A 工具调用 | PluginEval | 函数调用错误归因（选错 / 漏参 / 格式） | 诊断，不计分 | 公开 | 自动 |
| A 工具调用 | τ²-bench（retail / airline / telecom） | 多轮工具编排与双控 | 仅多轮场景 | 公开 | 自动 |
| A 工具调用 | **自建工具集（中文口语）** | 真实说法 → 工具与参数 | **主判据** | 自建 | 自动 |
| B 约束遵循 | IFEval | 25 类可验证约束（字数/格式/禁用词） | 格式与长度 | 公开 | 自动 |
| B 约束遵循 | **自建口语约束集** | 首句 ≤15 字、禁 markdown、禁列表 | **主判据** | 自建 | 自动 |
| C 忠实性 | FActScore 思路 | 原子事实可归因 | 辅助 | 公开 | 半自动 |
| C 忠实性 | HaluEval 中文子集 | 幻觉识别 | 辅助 | 公开 | judge |
| C 忠实性 | **自建数字/专名保真集** | 数字与专名原样搬运 | **硬门槛** | 自建 | 自动 |
| D 口语质量 | 人工成对比较 | 自然度、口语感、节奏 | **主判据** | 自建 | 人工 |
| D 口语质量 | LLM-judge rubric | 与人工校准后的批量打分 | 辅助 | 自建 | judge |
| E 时延 | 首 token / 整句 P50·P95（单并发） | 实时性 | 硬门槛 | 实测 | 自动 |
| E 时延 | 并发 1/4/8 的 P95 + OOM 边界 | 容量 | 硬门槛 | 实测 | 自动 |
| F 稳定性 | 同输入 5 次采样一致率、8k/32k 退化 | 抖动与长上下文 | 辅助 | 实测 | 自动 |

> 公开集出处：BFCL v4 见 Gorilla 官方榜；IFEval 见 arXiv:2311.07911；τ²-bench 见 ICML 2026；
> PluginEval 见 arXiv:2608.08700；FActScore / HaluEval 为公开可用基准（评分思路借用，中文需重写 rubric）。

### 3.2 每轴的选择依据

| 轴 | 为什么必须有 | 为什么只用这几个 |
|---|---|---|
| A 工具 | L3 的本地闭环能力靠它 | BFCL 覆盖标准切面，PluginEval 负责诊断，自建集负责真实中文说法；τ²-bench 只在需要多轮时启用 |
| B 约束 | 音色与可听性依赖长度与格式 | IFEval 是唯一成熟的可验证约束基准；口语长度约束它不覆盖，只能自建 |
| C 忠实性 | 转述改数字是最高危错误 | 数字/专名可用字符串精确判，最可靠；FActScore/HaluEval 只做交叉验证 |
| D 口语 | 公开集完全没有覆盖 | 只能用人工成对比较；judge 仅用于批量初筛 |
| E 时延 | 硬约束，榜单不给 | 必须自己压测，且要测量化版本 |
| F 稳定 | 抖动会放大成"时好时坏" | 同输入重复采样成本低 |

### 3.3 公开集的已知局限

| 局限 | 表现 | 应对 |
|---|---|---|
| 语言错配 | 以英文为主，中文口语覆盖薄 | 中文场景提高自建集权重（70% : 30%） |
| 精度错配 | 榜单多为 BF16 | 所有候选按部署量化（AWQ 4bit）重跑 |
| 提示错配 | 榜单用自己的 prompt 与 template | 统一 prompt/template/约束解码，否则不可比 |
| 数据污染 | 部分题可能进过训练集 | 私有改写 held-out（见 §7.1） |
| 难度错配 | 榜单题目超出/低于 L3 实际分布 | 只做淘汰，不做排位 |

### 3.4 自建集的必要覆盖

| 覆盖项 | 为什么必须自建 | 最小条数 |
|---|---|---|
| 承接语不越界 | 任何公开集都没有"只许说状态"的约束 | 40 |
| 数字/专名保真 | 需要精确比对而非语义相似 | 60 |
| 中文口语转述 | 口语省略、语气词、断句 | 60 |
| 空结果与超时 | 真实链路的必现分支 | 20 |
| 近邻易混（同一问法不同对象） | 检验槽位与指代 | 30 |
| 素材不足（必须说不知道） | 抑制编造 | 20 |

## 4. 自建评测集设计

### 4.1 素材来源与分层抽样

| 优先级 | 来源 | 占比建议 | 说明 |
|---|---|---|---|
| 1 | 真实语音转写（脱敏） | 50% | 分布最真，含口音与断句 |
| 2 | 后台真实输出（结论句 + 字段） | 30% | 转述题的天然来源 |
| 3 | 人工构造边界题 | 20% | 空结果、超时、素材不足、近邻易混 |

分层配比（标准档 300 条）：

| 分层 | 120 条（最小档） | 300 条（标准档） | 500 条（完整档） |
|---|---|---|---|
| 承接语 fill | 24 | 60 | 100 |
| 结果转述 narrate | 36 | 90 | 150 |
| 进度转述 progress | 12 | 30 | 50 |
| 直答措辞 answer | 24 | 60 | 100 |
| 工具调用 tool | 18 | 48 | 80 |
| 负例（不该说/素材不足） | 6 | 12 | 20 |

### 4.2 记录结构与"评行为不评字面"

```json
{
  "id": "narrate-012",
  "axis": ["C", "B"],
  "beat": "narrate",
  "user_utterance": "明天郑州天气怎么样",
  "material": {"conclusion": "明天郑州有雨，12 到 18 度", "facts": ["降水概率 80%"]},
  "expect": {
    "behavior": "narrate",
    "must_include": ["郑州", "12", "18", "80%"],
    "must_not": ["评价词", "素材外事实"],
    "max_first_sentence_chars": 15
  },
  "meta": {"source": "asr_log", "split": "heldout", "version": "v1"}
}
```

三条硬规定：

1. **禁止写"期望文本"**。写了就退化成文本相似度，模型换个说法就被判错。
2. `must_include` 只放可精确匹配的原子（数字、专名、单位）。
3. `must_not` 用类别而非穷举：`评价词`、`素材外事实`、`承诺语`。

### 4.3 五类判定方式

| 判定方式 | 用于 | 可靠性 | 成本 |
|---|---|---|---|
| 精确匹配（子串/正则） | 数字、专名、单位 | 高 | 极低 |
| 结构比对 | 工具 id + 参数键值 | 高 | 低 |
| 规则计数 | 字符数、标点、markdown 标记 | 高 | 极低 |
| LLM-judge（校准后） | 越界、加评价、口语自然度 | 中（κ≈0.5） | 中 |
| 人工成对比较 | 口语质量排序 | 高 | 高 |

原则：**能用精确匹配的，绝不用 judge。**

### 4.4 数据量与统计下限

每类样本量下限：

```
n ≥ z² · p(1−p) / e²        z=1.96, p=0.9
  e=±10% → 35（仅冒烟）
  e=±5%  → 138
  e=±3%  → 384
```

含义：单层少于 35 条的分数不要写进结论；想区分两个模型 3 个点的差距，单层需要 384 条。
所以"最小档 120 条"只能做淘汰，不能做精细排位。

### 4.5 质检与版本管理

| 检查 | 方法 | 门槛 |
|---|---|---|
| 素材可追溯 | 每条 expect 的原子必须来自 material | 100% |
| 配比正确 | 脚本统计分层条数 | 与 §4.1 一致 |
| 去重 | 句级 simhash | 重复 <3% |
| 与训练集隔离 | n-gram 重叠检查 | 13-gram 重叠 = 0 |
| 版本冻结 | `version` 字段 + 提交后冻结 | 评测中途不得改题 |

## 5. 打分与决策

### 5.1 硬门槛（不满足直接淘汰）

| 门槛 | 阈值 | 依据 |
|---|---|---|
| 数字/专名保真 | = 100% | 转述改数字是最严重的可信度事故 |
| 自建工具参数准确率 | ≥ 97% | 与《四层架构方案》§4.6 一致 |
| 越权工具调用 | = 0 | 安全底线 |
| 素材外编造 | = 0 | 同底线 |
| 首 token（单并发） | ≤ 350ms | 承接语覆盖窗口 |
| 24G + AWQ 并发 | ≥ 3 | 三路通话 |
| 量化掉点（BF16 → AWQ） | ≤ 3 分 | 部署形态必须可比 |

### 5.2 归一化

各集分数尺度不同（BFCL 是 0–100 准确率，人工比较是胜率），**禁止直接加权**。

```
z_i = (x_i − μ_group) / σ_group        // 候选群体内标准化
或
m_i = (x_i − min) / (max − min)        // 候选仅 2–3 个时用 min-max
```

候选少于 3 个时优先用 min-max（z-score 在 n=2 时退化为 ±1，信息量低）。

### 5.3 轴内合成与轴间加权

```
轴分 = 0.7 × 自建集z + 0.3 × 公开集z
总分 = 0.30×C保真 + 0.25×A工具 + 0.20×D口语 + 0.10×B约束 + 0.15×E时延
```

例外：D（口语）没有公开集，按 1.0 人工比较计；E（时延）是实测值，直接进 z 计算，不做自建/公开合成。

权重理由：

| 轴 | 权重 | 理由 |
|---|---|---|
| C 保真 | 30% | 错一个数字，用户信任直接受损 |
| A 工具 | 25% | 决定"能不能闭环" |
| D 口语 | 20% | 决定"像不像人"，用户感知最强 |
| B 约束 | 10% | 影响可听性，但可由模板兜底 |
| E 时延 | 15% | 硬约束，但已设门槛，此处只比余量 |

### 5.4 决策规则

| 条件 | 决策 |
|---|---|
| 任一门槛不过 | 淘汰 |
| 加权分差 < 5 分 | 选小模型（4B）——省资源、首字更快 |
| 加权分差 ≥ 5 分 | 选大模型（9B） |
| 分差在 4–6 分之间 | 看短板：转述输不能接受；工具输可以接受（可加约束解码补） |

### 5.5 算例（9B vs 4B，示意数据）

| 轴 | 9B | 4B | 9B z | 4B z | 权重 | 9B 贡献 | 4B 贡献 |
|---|---|---|---|---|---|---|---|
| C 保真 | 100% | 98.3% | +1 | −1 | 30% | +0.30 | −0.30 |
| A 工具 | 98.1% | 94.2% | +1 | −1 | 25% | +0.25 | −0.25 |
| D 口语 | 胜率 62% | 38% | +1 | −1 | 20% | +0.20 | −0.20 |
| B 约束 | 96% | 93% | +1 | −1 | 10% | +0.10 | −0.10 |
| E 时延 | 260ms | 180ms | −1 | +1 | 15% | −0.15 | +0.15 |
| 合计 | — | — | — | — | 100% | **+0.70** | **−0.70** |

（示例只示意算法，真实 z 值须按候选群体计算。）

结论：9B 总分领先 1.4 个标准差，且 4B 在保真轴上不达标（98.3% < 100%），先被门槛淘汰。

## 6. 冲突裁决与一致性检验

### 6.1 同轴多集的一致性

```
Kendall τ（或 Spearman ρ）≥ 0.6  → 该轴结论可信
τ < 0.6                          → 该轴存在污染或难度错配
```

处置：换 held-out 子集重跑；仍 <0.6 则弃用其中一个集，并在报告里写明原因。

### 6.2 跨轴冲突

| 冲突形态 | 裁决 |
|---|---|
| 大模型工具强、小模型转述强 | 转述优先（用户感知最强，且难以用工程手段补） |
| 公开集说 A 好、自建集说 B 好 | 以自建集为准 |
| 时延与质量冲突 | 先看门槛，再看"承接语能否覆盖" |

### 6.3 公开集的作用边界

公开集可以用来：

- 淘汰明显不达标的候选
- 与外部（同事、厂商、竞品）沟通时提供共同语言
- 交叉验证自建集结论是否离谱

不能用来：

- 单独决定选型
- 证明"可以上线"（它不覆盖你的分布）

## 7. 防污染与对齐

### 7.1 私有改写 held-out

每个公开集抽 20% 做三件事，只报改写后的分数：

| 改写 | 例子 | 目的 |
|---|---|---|
| 同义改写 | "把灯打开" → "帮我开一下灯" | 破坏 n-gram 记忆 |
| 数值替换 | 城市、时间、金额换掉 | 破坏答案记忆 |
| 选项打乱 | 多选项顺序随机 | 破坏位置偏好 |

判读：改写后掉分 >10 分 → 疑似污染，该集降权或弃用。

### 7.2 执行一致性（不做这步，多集全白跑）

| 项 | 必须统一 |
|---|---|
| prompt / system | 同一份字符串 |
| chat template | 与基座一致 |
| 约束解码 | 同开或同关（工具分支必须开） |
| 量化 | 全部 AWQ 4bit |
| 采样参数 | temperature / top_p / max_tokens 固定 |
| 并发 | 压测报告注明并发数 |

### 7.3 judge 校准

2026 年两项系统性研究（arXiv:2606.19544 评测 21 个 judge；arXiv:2606.13685）指向同一结论：
**主观任务上跨 judge 一致性只有 κ≈0.51**，接近随机。因此：

| 规则 | 说明 |
|---|---|
| judge 与被测模型不同源 | 同源会系统性偏高 |
| 人工复核 20% | 逐条比对 judge 与人的判定 |
| 一致率 <0.7 | 换 judge 或把主观项拆成可判子问题（如"是否出现素材外数字"） |
| judge 只做初筛 | 最终分以人工复核后的为准 |

## 8. 执行流程与预算

### 8.1 三档预算

| 档位 | 工期 | 包含 | 适用 |
|---|---|---|---|
| 最小 | 1 天 | BFCL 子集 + 自建 120 条 + 时延 | 淘汰明显不行的候选 |
| 标准 | 3–5 天 | BFCL v4 + IFEval + 自建 300 条 + judge 校准 + 并发与量化对比 | **正式选型（推荐）** |
| 完整 | 2 周 | + τ²-bench + FActScore 改写 + 影子 3 天 | 立项评审前 |

### 8.2 两周标准流程

| 日 | 任务 | 产物 |
|---|---|---|
| D1–D2 | 造 300 条（真实转写 + 后台输出 + 构造边界） | `eval/selfbuilt_v1.jsonl` |
| D3 | 跑候选（9B AWQ / 4B AWQ / 一个云端对照） | 每候选一份 per-item CSV |
| D4 | 跑 BFCL v4 子集 + IFEval | 公开集分数表 |
| D5 | 时延实测：首 token、整句、并发 1/4/8 | `latency.csv` |
| D6–D7 | judge 初筛 + 人工复核 20%，算一致率 | `judge_calibration.md` |
| D8 | 汇总打分（z/min-max + 权重 + 门槛） | `decision.md` |
| D9–D10 | 影子模式旁路跑 3 天（只看不播） | `shadow_report.md` |

### 8.3 产物清单（harness 建成后）

| 产物 | 说明 |
|---|---|
| `eval/suite.yaml` | 轴、集、权重、门槛的唯一定义 |
| `eval/selfbuilt_v1.jsonl` | 自建集（冻结版本） |
| `eval/runner.py` | 统一跑批（同 prompt / 同量化） |
| `eval/aggregate.py` | z-score、加权、τ、门槛判定 |
| `eval/report/decision.md` | 选型结论与证据 |

## 9. 风险与反模式

### 9.1 五个反模式

| 反模式 | 后果 | 纠正 |
|---|---|---|
| 拿榜单排名直接拍板 | 选到"榜单强、场景弱"的模型 | 榜单只做淘汰 |
| 同一轴堆三个集 | 该轴权重被隐式放大 | 每轴 ≤2 集，轴内合成 |
| 用期望文本做标注 | 退化成相似度，换说法就判错 | 评行为不评字面 |
| judge 一把梭 | κ≈0.5，结论不可复现 | 客观项自动判 + 主观项人审 20% |
| 用 BF16 分数代表部署效果 | 量化掉点 2–5 分被忽略 | 全部按 AWQ 4bit 重跑 |

### 9.2 风险与对策

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 评测集被训练污染 | 改写后掉分 >10 | 弃用该集或只用 held-out |
| 自建集分布偏 | 线上影子与离线差 >10% | 每季度用真实日志补题 |
| 标注者口径不一 | 双人标注 κ <0.6 | 先写标注手册再标注 |
| 结论不可复现 | 两次跑分差 >3 | 固定随机种子与采样参数，记录版本 |
| 过度优化评测集 | 线下涨、线上不涨 | 影子模式为准，离线只做准入 |
