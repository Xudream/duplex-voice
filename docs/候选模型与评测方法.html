> 配套：尺子1构建报告.md（数据规模）、sidetalk评测集构建方案.md（口径）、拒识sideTalk设计文档.md（模块边界）

1. 候选池：两条跑道

1.1 跑道 A：文本裁判（主跑道）

输入 = 转写 + 系统态 + 5 轮历史；输出 = 动作 JSON。这是"外挂裁判"路线的最小验证形态。

#候选形态部署成本口径【估算】为什么进候选备注
A0规则 + 字符 n-gram/BERT 分类器判据可解释端侧/CPU0必跑基线：不跑它不知道 LLM 到底加了多少分用 train 集训，测试集不碰
A1Qwen3-0.6B开源 LLM端侧 NPU 可行电费端侧 L2 的最低成本档指令遵循弱，看它能否守住协议
A2Qwen3-1.7B开源 LLM端侧/单卡电费端侧 L2 主力候选需实测 NPU 延迟（10–50ms 存疑）
A3Qwen3-4B开源 LLM单卡 A10/A100电费精度与端侧折中量化后显存 ~3GB
A4Qwen3.5-4B开源 LLM单卡电费新代际，中文更强需核对许可与量化可用性
A5Qwen3.5-9B开源 LLM24G 卡电费强基线（也是 L3 小脑候选）延迟偏高，适合做 L3 复判
A6DeepSeek-V4-Flash托管 API云按 token低价快模型需确认是否支持 JSON 约束
A7DeepSeek-V4-Pro托管 API云按 token强推理，做 L3 强分支不适合每轮调用
A8GLM / 豆包（各取一档）托管 API云按 token横向对照，避免单一供应商偏差用同一 prompt
A9Jev（TypeSafe System One）有界决策模型托管 API（无权重）$0.042/M input决策型模型的代表：0% 类型错误、带校准置信度不能端侧；需评估数据出境

> 跑道 A 里 A0 是必跑项，A1–A9 建议全跑（成本 < ¥100），因为裁判模型的差异往往只有 2–4pt，样本量足够才能分辨。

1.2 跑道 B：端到端语音模型（对照组）

输入 = 原始音频；输出 = 响应/静默。用来量化"模型自带拒识"的上界，以及外挂路线还差多少。

#候选形态可私有化拒识相关公开证据备注
B1Qwen-Audio-3.1-Realtime云端实时否FD-Bench v1.5 背景语音响应 73%→13%官方文档明确支持 smart_turn + 说话人增强
B2豆包 Seeduplex 3.0云端实时否端到端全双工；官方文档需确认是否开放"拒识/静默"显式控制
B3腾讯 Gander开源（Apache-2.0）是FD-Bench v3 接管 100% / 抢话 8.0%自部署成本高（≈9B），适合做上界参照
B4GLM-Realtime云端否音视频通话，2 分钟记忆价格 0.18 元/分钟（音频）
B5Step-Audio 2 mini开源是URO Bench 开源最高（自报）轻量，适合跑通链路
B6Moshi开源是全双工可打断英文为主，做参照

2. 评测方法（可直接执行）

2.1 四组实验矩阵

组跑道输入目的
E1Agold 转写裁判能力上限（排除 ASR 干扰）
E2A真实 ASR 转写真实链路能力（与产品一致）
E3B原始音频端到端上界
E4Agold 转写 + 打乱历史消融：历史到底有没有用

E1 与 E2 的差值 = ASR 误差传导，这是决定"要不要为 ASR 升级付费"的唯一硬证据。

2.2 统一动作协议


{"action":"respond|ack|wait|clarify|silent|silent_record","confidence":0.0,"reason":"≤20 字"}

解析规则（llm_judge.py 已实现）：

  1. 非 JSON / 动作越界 → invalid（单独计数，>1% 该模型出局）
  2. clarify 单列，不计入拒识率分子、不计入 FAR
  3. silent_record 与 silent 在指标上等价

2.3 三阶段执行

阶段样本目的通过条件
冒烟每集 100 条（分层抽）验证协议、暴露 prompt 问题invalid <1%、无 429
全量2,595 条（音频就位部分）出正式表全部模型同批样本
复跑全量的 10%稳定性（temperature=0 应 100% 一致）不一致率 <1%，否则查采样

2.4 指标与统计

指标口径
分场景拒识率按 S1/S2/S3 分别出（S4 暂无样本）
FAR_wΣ w_s(1−Rej_s)，w = S1 0.40 / S2 0.15 / S3 0.25 / S4 0.20（缺项自动归一）
FRRS0 被置静默的比例（S0_guest 单列，不计入）
误执行一票否决
决策延迟P50/P90（从提交到拿到动作）
工作点扫 confidence 0.05–0.95，报「FAR_w=5% 处的 FRR」与「FRR=3% 处的 FAR_w」
显著性Wilson CI；同批样本两模型用 McNemar；AUC 差用 bootstrap 1000 次；多模型 Holm 校正

报数纪律：差异小于 CI 宽度就写"不可区分"。当前样本量下（见 §3）可分辨的最小差异约 2–4pt。

2.5 淘汰与提名

硬淘汰（任一触发）：误执行 >0、invalid >1%、S1 拒识 <80%、P90 延迟 >800ms、无法私有化。

通过后按 §1.3 加权排序，取前 2 名进入尺子2（自建集 + 真机）。

2.7 复现命令


cd ~/repos/projects/duplex-voice/tools/ruler1
DATA=~/.hermes/workspace/ruler1/data
# 生成清单（含 audio_ok 标记）
python3 build_manifests.py --dataset all --data $DATA --out manifests

# 冒烟：先跑 100 条
python3 llm_judge.py --manifest manifests/chorus.jsonl --backend openai_compat \
  --base-url https://dashscope.aliyuncs.com/compatible-mode/v1 --model qwen-plus \
  --limit 100 --out predictions/qwen-plus__chorus__smoke.jsonl
python3 score.py --manifest manifests/chorus.jsonl \
  --pred predictions/qwen-plus__chorus__smoke.jsonl --only-predicted --sweep

# 全量：同一条命令去掉 --limit；换模型只改 --model / --base-url
