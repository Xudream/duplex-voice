1. 拒识的场景分析

1.1 HumDial 口径

ICASSP 2026 HumDial Challenge 把 Track II 的拒识拆成四类：

缩写全称中文系统应有动作
URBuser real-time backchannels用户实时附和静默继续（不打断）
PHpause handling停顿处理等待，不抢话
TPSthird-party speech第三方在说话静默
SDOspeech directed at others对他人说的话（sidetalk）静默 + 记上下文

sidetalk ≈ SDO（主用户转向旁人），TPS 是它的相邻场景（背景里别人在聊，主用户没参与）。

来源：HumDial Challenge 官网 · 论文 arXiv:2601.05564 · GitHub ASLP-lab/Hum-Dial。论文原文口径：Rejection 考察 "robustness against non-instructional speech such as user real-time backchannels (URB), pause handling (PH), third-party speech (TPS), and speech directed at others (SDO)"；Track II 总分 = 0.4×Interruption + 0.4×Rejection + 0.2×First Response Delay，拒识相关指标为 Rejection Rate、Early Interrupt Rate。主办方含西北工业大学、南大、清华、剑桥、华为、AISHELL 等；数据为 LLM 生成脚本（DeepSeek）+ 专业演员真实录制。测试集构成（论文 Table 1，与 FDBench GitHub 仓库 README 分布表一致；HF 数据集页 README 为空、仅 license 行）：拒识 2,000 = URB 600 / PH 600 / TPS 600 / SDO 200，打断 3,000；SDO 测试仅 200 条（Wilson 95%CI ≈ ±4.2pt，子类差异 <4pt 统计不可区分，解读时注意）；SDO 定义（FDBench GitHub 仓库 README 原文）："the user temporarily addresses another person, often on an unrelated topic, and the system is expected to detect and ignore such speech"。语言口径（已定论）：Track II 为中英双语——官方 Track II 榜单将 Interruption / Rejection 分 CN、EN 两列分别计分，双语结构由榜单本身确证（解压测试包后按语言分桶即可）。

1.2 VGBench 口径

类型定义例子文本层是否可分
side-talk主用户对旁人说话"帮我把这个放桌上"（对同事）不可分（与指令同形）
self-talk自言自语"嗯……这个放哪来着"部分可分（无请求对象）
speaker-switch同一句话换说话人/距离/时间边界同一句指令由旁人说 vs 穿戴者说完全不可分

speaker-switch 是三者中最难的：词不变、只有来源变，任何纯文本模型都无能为力。

> 口径提示：三分类同属"该不该响应"（addressedness）问题家族；self-talk 与 side-talk 的区分维度是有无交流对象。注意：VGBench 三分类 ≠ 本模块支持范围——side-talk 对应本模块 S1，self-talk 不进本模块 v1 支持清单（判定复用本模块裁判、评测单列），speaker-switch 由身份层信号保障，详见 1.3.0/1.3.1。

来源：VGBench 论文 arXiv:2609.32536——"a 1,018-item diagnostic benchmark for action-level addressedness across side-talk, self-talk, and speaker-switch scenarios"（1,018 条动作级 addressedness 诊断集）。

1.3 我们对 sideTalk 场景的定义

1.3.0 总定义与模块边界

产品形态与场景范围：本方案的主场景为家庭智能音箱（固定放置、远场拾音、家庭多成员环境）与手持设备（手机，近场为主、随人移动、常伴随外放媒体）；智能眼镜为补充场景（v2 预留），其多通道空间信号与结论仅作参考，不计入 v1 验收。

定义：sideTalk 指"语音在拾音范围内，但不是对系统说的"。sideTalk 拒识模块的职责是：对这类语音保持静默、不产生任何响应，同时不破坏正在进行的人机对话状态（不终止会话、不打断当前播报、不吞掉随后的真实指令）。

模块边界：本模块解决的是归属问题（谁在说、对谁说），不解决时机问题（该不该现在开口）。因此：

问题举例归属模块
时机问题：这话该不该现在响应？用户附和（"嗯/好的"）、用户停顿思考（"那个……"）语义 VAD / 轮次决策模块（本模块不涉及）
归属问题的特殊子类：指向无人自言自语（self-talk，无交流对象）复用本模块裁判、评测单列（v1 场景清单外，见下）
归属问题：这话是不是对我说的？主用户转向旁人、旁人闲聊、媒体人声sideTalk 拒识模块（本文档）

对齐公开口径：HumDial 四类中，SDO、TPS 属本模块，URB、PH 属语义 VAD；VGBench 三类中，side-talk 属本模块，self-talk（自言自语）在业界是与 side-talk 并列的独立 addressedness 子场景（VGBench 三分类、DUPLEX-MPE 负例 N3 均将其单列，区分维度是"有无交流对象"），不属于本模块 v1 支持清单，但其判定复用本模块裁判（见 1.3.3），评测单列；speaker-switch 靠本模块的身份层信号（声纹/DoA）保障。

1.3.1 场景定义与清单

sideTalk 模块支持 4 个场景（S1–S4），另设 1 个对照场景（S0）——S0 不属于本模块，列出它是为了度量拒识的代价：

编号场景说话人交流对象典型样例系统动作
S0真指令 / 答句（对照场景）主用户系统"今天天气怎么样"响应（正常链路；本模块不得误吞）
S1主用户转向旁人（SDO，核心场景）主用户第三方在家对家人说"帮我把酱油递一下"；办公室对同事说"帮我把这个放桌上"静默 + 记上下文
S2旁人对主用户说话（B1）旁人主用户"你手机响没响？"静默（可选摘要级记录）
S3旁人之间的对话（B2）旁人旁人家人之间闲聊（音箱场景）、咖啡馆邻桌（手机场景）静默
S4媒体 / 电子人声（B3）电子源—电视台词"把枪放下"（音箱场景高频）、手机外放短视频/语音消息静默，防指令式台词带偏

核心难点在 S1：它与 S0 文本同形——"帮我把这个放桌上"既可能是对助手下指令，也可能是对旁人说话，纯文本不可分，必须依赖带外信号（见 1.3.2）。S1 的语音进入旁听缓存（带时间戳与说话人标签），默认不参与回答，仅当用户显式引用时才可使用——这是隐私与体验的双重边界。

范围外（明确不做，防止口径漂移）：

  • 附和（URB）、停顿（PH）：时机问题 → 语义 VAD；
  • 自言自语（self-talk）：主用户、无交流对象——业界（VGBench、DUPLEX-MPE）将其列为与 side-talk 并列的独立 addressedness 子场景（非时机问题），判定复用本模块裁判，但 v1 不列入支持场景清单，评测单列（自建集覆盖）；
  • 访客指令（旁人对设备说"小X，放首歌"）：涉及声纹白名单与隐私策略 → v1 不做，留开关；
  • speaker-switch 作为独立类型不单列：其判定 = "旁人说出的指令"，由 S2–S4 的身份层信号覆盖（旁人对设备下指令的访客指令除外，见上条），并在自建对抗集中强化测试（4.4 阶段 2）。

1.3.2 判定信号（四层，供 4.3 裁判使用）

层信号强度对哪个场景关键
① 说话人身份层主用户声纹（闭集判定"是否机主"）；距离/朝向声学特征——音箱：环形麦阵 DoA + 远场波束（区分室内谁在说话、是否对设备）；手机：近讲检测（近场能量比、持握姿态对麦克风的声道差）最强，文本无关S2/S3/S4 的主判据；S1 的第一步分流
② 语义层请求句式（祈使句、"帮我/给我"）、称谓（唤醒词/助手名）、与当前对话的衔接度（承接系统上一句 → 大概率答句）中，可被同形文本欺骗仅对 S1 关键（S1 与 S0 同形，靠语义做最后分辨）
③ 时序层出现在系统提问之后（答句）vs 播报之中 vs 与当前对话无关中S1 的辅助判据
④ 多模态层（可选）音箱：设备态（是否正被使用、媒体是否外放中）、房间活动感知；手机：屏幕朝向/握持态、前台应用态（导航/通话中默认更保守）、是否外放中。眼镜（补充场景）另有注视/朝向可用增强S1 与 S4（外放中 → 媒体人声概率大增）最有用

1.3.3 决策逻辑

本模块对每段语音按两步判定：

第一步：说话人是谁（身份层，文本无关）

  • 是主用户（声纹命中） → 进入第二步；
  • 不是主用户 → 是媒体源吗？（声学事件检测/设备状态）是 → S4 静默；否 → 与主用户有交流关系吗？（朝向、距离、语义衔接）有 → S2 静默；无 → S3 静默。

第二步：主用户的话指向谁（语义层 + 时序层 + 多模态层）

  • 指向系统（承接系统提问、含唤醒词/请求句式、朝向设备） → 放行给正常链路（S0）；
  • 指向第三方（朝向旁人、交流对象是具体的人、与当前对话无关） → S1 静默 + 记上下文；
  • 指向无人（无交流对象、无话题衔接） → self-talk：动作同为静默（不记上下文）——判定复用本模块裁判，但不属 v1 支持清单（见 1.3.1 范围外），评测单列；
  • 无法判定（低置信度） → 按语义信号分两路，避免一刀切静默吞掉真指令：
  • 含请求句式或承接系统上一句 → clarify 轻确认（如"您是说把空调调到 26 度吗？"——出声但不执行、不计为误响应；单列 clarify 率监控，目标 ≤ 2%）；
  • 否则 → 静默 + 记上下文（宁可少说，不可说错；旁听缓存保留后续引用的可能）。

与相邻模块的边界：

相邻场景判别特征归属
附和（URB）/ 停顿（PH）主用户、短促反馈或话轮未完语义 VAD / 轮次决策模块
自言自语（self-talk）主用户、无交流对象独立 addressedness 子场景：复用本模块裁判（第二步"指向无人"分支），v1 场景清单外、评测单列
真实打断（barge-in）主用户、有请求、发生在系统播报中主链路（sideTalk 的相反面：明确接受）
唤醒词出现任何说话人说出唤醒词/助手名v1 仅主用户声纹唤醒生效；对 S3/S4 是兜底规则

1.3.4 指标定义（与 4.2 对齐）

拒识类指标（拒识率 / FAR / 误执行）只在 sideTalk 场景（S1–S4）的样本上统计；FRR 在 S0（真指令）样本上统计：

  • 拒识率（Rejection Rate）：应静默样本中正确静默的比例，按 S1–S4 分别统计；
  • 误响应率（FAR）：应静默样本上产生完整响应或执行工具的比例，全场景加权聚合 FAR = Σ w_s × (1 − Rej_s)（w_s 按产品真实流量占比，看板按实算）——它是分场景拒识率的联动视图，不设独立常数门槛（否则与分场景目标可能数学上互斥）；clarify 轻确认不计入 FAR，单列监控；
  • 误执行：应静默样本上触发工具调用等高危动作的次数——一票否决项，目标恒为 0，不设阈值；
  • 漏响应率（FRR）：真指令（S0）被本模块误吞的比例——拒识的代价项，与语义 VAD 模块共同承担；承诺值 ≤ 3%（当前 S0 可用样本 n≈700–800 时 Wilson 95% 半宽约 ±1.0pt，3% 是可统计证明的上界；≤ 2% 为内部目标，待尺子2 S0 扩充至 ≥ 3,000 段后生效）；
  • clarify 率：clarify 动作发生的频率（监控指标，目标 ≤ 2%；clarify 出声但不执行，用户可感知但无害）；
  • 静默决策延迟：从应静默语音结束到系统确认不响应的判定窗。闭合条件：拒识判定基于 partial ASR（流式部分识别结果，不等 final），由 L1+L2 在窗内完成（30 + 300 + 10 + 50 ≈ 390 ms < 500 ms）；L3 复判异步进行（快分支 ~300 ms，超时回退 L2 结果），不阻塞静默判定与正常响应链路。

综合目标（sideTalk 模块整体）：

  • 各场景分项达标（上表 S1–S4）即为综合达标；误执行 = 0（一票否决）；
  • FAR 为加权监控视图（公式见 1.3.4），随看板实算，不设独立门槛；
  • FRR 承诺 ≤ 3%（统计可证明上界；内部目标 ≤ 2%，待 S0 扩充后生效）；
  • HumDial Track II：SDO 子集拒识率 ≥ 90%、TPS ≥ 95% 为承诺目标——但 HumDial 仅作对外坐标 + 回归尺子（SDO 200 条 ±4.2pt / TPS 600 条 ±1.8pt，模型间 <4pt 差异统计不可区分），选型主分辨器为 CoDeTT SideTalk 子集（2,000 条，±1.3pt）+ 自建集；官方榜单 Rejection Total Score（Baseline 35.2 / 冠军 72.2）为整系统参照坐标，不作为承诺目标；
  • 静默决策延迟 ≤ 500 ms（闭合条件见 1.3.4：partial ASR + L1/L2 窗内完成 + L3 异步）；正常响应首延迟 P90 ≤ 800 ms（不因本模块变慢）；
  • self-talk 作为独立 addressedness 子场景单列评测（不进 S1–S4 目标表；VGBench 实证其为高难场景，原始模型静音率仅约 52%），v1 先观测基线、目标随数据补充后另定；
  • 时机类指标（误打断率 ≤ 8%，参照 Gander FD-Bench v3 抢话率）由语义 VAD 模块承担，本项目只做回归验证、不设开发目标；
  • 以上指标在 4.2.1 公开集与 4.2.2 自建集同口径考核，4.4 穿刺各阶段以本表为 Go/No-Go 依据。

3. 业界方案洞察

3.1 外挂LLM，系统判断

模式定义：拒识与时机决策不训进语音模型，而是架设在传统语音链路之上，由一个（可外挂的）LLM 担任"裁判"，输出结构化决策，由系统执行。拒识策略以提示词/规则形式存在，可热更新、可审计。

通用链路：


音频前端（AEC/NS/波束成形）
  → VAD
  → 说话人模块（声纹 + DoA/近讲检测）
  → 流式 ASR（增量转写 + 词级时间戳）
  → 拒识裁判【多级：L1 规则/信号 → L2 端侧小模型 → L3 云端 LLM 复判】
  → 决策动作 { respond / acknowledge(附和) / wait(等待) / silent+record(静默+记上下文) / silent }
  → 对话与任务执行（回复 TTS / 工具调用 / 旁听缓存写入）

三级拒识漏斗（延迟从低到高）：

级判断依据延迟挡掉什么
L1 信号/规则层声纹白名单、唤醒词、能量、DoA、媒体源标识< 10 ms（端侧）大部分 TPS/B3：非主用户声纹直接静默
L2 端侧有界决策端侧 NPU 小模型（Qwen3-0.6B/1.7B 量化）做动作级判定（Choice + escape）10–50 msself-talk、明显闲聊、大部分 SDO 歧义
L3 云端复判（异步）快分支：Jev 类决策模型（有界动作，~300 ms【第三方实测】，带校准置信度）；强分支：带多轮上下文与场景态的 LLM，输出结构化 JSON（action/reason/confidence/record_flag），100–500 ms快分支 ~300 ms；强分支 100–500 ms（云/边）L1/L2 无法判定的文本同形 SDO 歧义 case；L2 低置信度分流

优点：决策可审计（每条拒识留 JSON 依据）；策略可热更新（改提示词/规则不发版）；无需重训端到端语音模型；隐私可分级（声纹/DoA 不出端，语义模糊 case 才上云）。

缺点：链路长、时延叠加；ASR 错 → 裁判错判的错误级联；旁听缓存与主对话状态机的上下文管理复杂（需隔离）。

业界代表：

  • 华为小艺（见 3.1.1）；
  • Meta 在 WearVox 上验证的"Whisper ASR + 文本 LLM"两段式 pipeline——单通道下 side-talk 拒识 85.6%，接入多通道空间信息后升至 93.9%：说明外挂路线可达标，瓶颈在前端空间信息而非裁判本身（WearVox 论文）；
  • 阿里 Qwen-Audio-Agent 的 Frontend Agent（harness 模式）：前端 Agent 解释流式输入、维持全双工对话、在直调工具与后台委派之间选择——本质也是"系统判断 + 外挂大脑"（arXiv:2609.25195）；
  • TypeSafe Jev（System One 决策模型，2026-09-15 发布）：无 LLM 的语音 Agent 参考栈（Deepgram Flux STT → Jev → TTS），每决策约 300ms、带校准置信度、0% 类型错误——证明"有界转录判断"可以不依赖 LLM（Evalgent 解析）。

3.1.1 小艺方案

华为未发表小艺拒识链路的论文级细节，以下为公开资料还原（官方支持文档、产品页、公开报道），供对标；与本团队"外挂 LLM、系统判断"的路线判断一致：

  1. 系统级"对话中控"，先决策、后内容。 华为云盘古 Bot 公开架构中，"对话中控（多轮问答理解、意图识别、分发）"被定位为"整个对话系统的核心枢纽"，之下才是助手编排与插件调用（盘古 Bot 架构）。小艺在终端侧同理：语音先被中控判断"是什么、归谁管"，再分发执行——判断与内容生成解耦。
  2. 全双工连续对话 + 拒识过滤。 小艺支持免唤醒连续对话；公开科普口径中，拒识的功能即"把无效的语音过滤掉"（周围人说话、背景噪音），多轮对话依赖连续会话的上下文缓存（全双工连续对话与拒识）。
  3. 声纹私语——身份层的产品化。 小艺提供"小艺私语"开关（设置 > 小艺 > 唤醒/唤醒与对话）：基于声纹识别，仅对已注册机主的语音做出响应（官方说明）——正是 1.3 中"说话人身份层（最强信号）"的落地：闭集声纹判定在端侧完成，非机主直接静默。
  4. 多模态场景态辅助判断。 "边聊边看"模式下摄像头与语音同时输入（官方支持页）；HarmonyOS 系统级感知（前台应用、屏幕状态、位置、是否通话中等 200+ 数据点）可作为裁判的场景特征。
  5. 分级隐私。 声纹、唤醒等敏感信号不出端，语义模糊 case 才上云（盘古大模型，Celia 自 2023 年起接入 Pangu 3.0）复判。

对齐到 1.3 的四层信号：小艺 = 身份层（声纹私语）+ 语义层（中控意图识别）+ 多模态层（系统感知/边聊边看），时序层内化在连续对话状态机中。

补充（业界专利）：语义层面拒识判断模型（CN107665708B 智能语音交互方法及系统）、含唤醒词的全双工语音拒识方法（聚好看专利申请报道）。

3.2 语音模型的两类形态

按"语音是否直接进入模型"，业界语音模型分两类：

  • 语音直入型（端到端）：音频直接进模型、无 ASR 文本瓶颈，拒识与时机可训进模型，但策略固化、不可热更；
  • 基于文本型（级联）：语音先转文本（ASR）再交给文本 LLM，拒识依赖外挂判断（3.1 模式），策略可热更、可审计，但受 ASR 正确率制约。

4. 模型选型及技术穿刺

4.1 方案建议

类似小艺，外挂 LLM 判断。 落到本系统（家庭智能音箱 + 手机为主场景，免唤醒连续对话、中文为主；智能眼镜为补充）：

  • 不做端到端重训：复用现有语音链路，新增"拒识裁判"模块（L1 规则/声纹 → L2 端侧小模型 → L3 云端 LLM），策略全部可热更。
  • 统一决策协议：裁判输出 {"action": "respond|ack|wait|clarify|silent|silent_record", "who": "primary|other", "reason": "...", "confidence": 0~1}；silent_record 时附带旁听缓存写入（默认不参与回答）；clarify 为低置信度兜底的轻确认动作（出声不执行，见 1.3.3）。按 1.3 的模块边界，sideTalk 模块只消费归属类动作（respond 放行 / silent / silent_record）；ack、wait 供语义 VAD 模块消费——同一裁判、两个下游，评测时 sideTalk 指标只看归属三类。
  • 前端按设备形态补空间/距离信息——音箱：环形麦阵 DoA + 远场波束（家人在不同方位、是否朝设备说话可分）；手机：近讲检测 + 持握/放置姿态。WearVox 官方案例研究证明空间信息是 side-talk 拒识最大增益（单→多通道 85.6%→93.9%、整体 61.9%→66.4%），该结论跨形态方向一致，具体增益量级由尺子2 在音箱/手机上实测。
  • 保留端到端模型作对照组与兜底（见 4.3/4.4）。

  • 输入构造：对话式推入——系统态（idle/speaking）+ 双通道音频流 + 既有对话历史转写；复现官方评测环境（标准化 Docker + RTX A6000，延迟分取官方脚本口径）。
  • 判分：以官方脚本输出为准（Rejection Rate / Early Interrupt Rate / First Response Delay）；本模块侧另计"每子类拒识率"与误执行（0 容忍）。
  • 对标：SDO 子集拒识率 ≥ 90%、TPS ≥ 95% 为承诺目标；官方 Rejection Total Score（Baseline 35.2 / 冠军 72.2）为整系统参照坐标（总分含打断与延迟分量，不作为本模块承诺）。

② CoDeTT（诊断尺子）——具体做法

  • 获取：HF 数据包，lz4 -dc CoDeTT.lz4 | tar -x 解压即得中英 × 真实/合成 × 系统态的完整目录（jsonl + 音频）。
  • 子集抽取：仅 SystemIdle_Dismiss_SideTalk.jsonl 与 SystemSpeaking_Maintain_SideTalk.jsonl 两类进 sideTalk 指标（→S1）；其余 12 类意图子集全量跑但不计指标。
  • 输入构造：每实例 = 系统态 + 5 轮对话历史 + 当前目标语音；统一问"此刻应执行哪个动作"。
  • 判分：官方两阶段协议——4 动作（Maintain/Stop&Listen/Takeover/Dismiss）ACC；对动作正确的样本再核意图是否同向算 SMR（语义错配率）。映射到我们的协议：Dismiss→silent、Takeover→respond、Stop&Listen/Maintain→语义 VAD 域动作（仅回归核对"本模块未把它判成归属错误"）。
  • 诊断用法：把错误分三桶——"没识别出归属"（ACC 错）、"识别了不肯闭嘴"（应 Dismiss 给了 Takeover）、"蒙对理由错"（ACC 对但 SMR 命中）——分别反哺 L1/L2/L3。

③ WearVox（补充尺子，眼镜形态）——具体做法

  • 获取：HF 数据集，取 Side-Talk Rejection 任务 1,082 条（582 side-talk + 500 有效 query）。
  • 子集抽取与映射：side-talk 条目（旁人语音）→S2/S3；valid queries（真指令）→S0 对照，构成"拒识率 × FRR"的配对检验。
  • 输入构造：先单通道 audio_query 跑全量；再对多通道版用 audio_query_mc 复跑——两轮差值即空间信息增益（官方参考：85.6%→93.9%）。注意数据为眼镜第一视角录制，与音箱远场/手机近场的声学几何不同，增益方向可参考、绝对值不迁移——主场景增益以尺子2 实测为准。
  • 判分：二分类（silent=拒识正确 / 非 silent=失误）+ S0 侧答对率；与官方两段式基线（Whisper+GPT-5）和业界区间（论文口径：实时 SLLM 整体准确率 29%–59%）对照。
  • 定位声明：仅英文、仅眼镜形态——不进主场景验收；用于三点参考：裁判复判能力迁移性、空间信息增益方向、WearVox 论文口径（实时 SLLM 整体准确率 29%–59%）的难度标定。

④ ChorusDuplex-SideTalk（中文冒烟尺子）——具体做法

  • 获取：HF 数据集（CC BY 4.0），clean 100 段 + babble 100 段；timeline.json 提供逐轮绝对时间戳。
  • 子集抽取与映射：按 annotations.jsonl 逐轮判——kind=side_talk（134 轮）→S1；speaker=third_party 的轮→S2/S3；assistant 轮→S0 对照；kind=backchannel/interruption 的轮→仅回归（语义 VAD 域）。
  • 输入构造：按 timeline 切段推入，stereo 布局（L=非助手声道、R=助手声道）与我们的双流前端直接对齐。
  • 判分：逐轮 gold = addressee + kind 推出的应静默/应响应标签；clean 与 babble 两版分别出数，差值即背景人声鲁棒性。
  • 用法：CI 冒烟——每次模型/规则/提示词变更必跑必过；也是尺子2 采集前的链路试跑场。

统一测评方法（跨集通用规则）：

  1. 输入构造三要素固定：音频（按各集声道布局）+ 系统态（idle/speaking，CoDeTT 与 HumDial 显式给定）+ 多轮历史（转写文本，取各集自带标注）；半双工实现只测 idle 态并在看板标注。
  2. 判分以规则为主：动作级 gold 直接判对错，无需 LLM judge；仅 respond 的内容质量用冻结版 LLM 判分器——与官方 scoring judge 完全一致：Qwen/Qwen3-Omni-30B-A3B-Instruct（HumDial 官方 GitHub 确认），判分 prompt 与版本号入仓锁定。
  3. 指标公式（与 1.3.4 同口径）：子类拒识率 = 该子类正确静默数 / 应静默总数（S1–S4 分别出）；FAR = 1 − 加权拒识率；误执行单独计数（0 容忍）；FRR = S0 被误吞数 / S0 总数；静默决策延迟 P50/P90。
  4. Sanity check：每接入一集，先复现已公布基线（WearVox 两段式 85.6% 一线、CoDeTT 官方基线、HumDial Baseline 35.2），偏差 > 3 pt 判 harness bug，修完才开跑被测系统。
  5. 回归纪律：时机类子集（URB/PH/Backchannel 等）每次变更必跑，验证"sideTalk 模块的变更不引起语义 VAD 域指标退化"；退化即回滚。
  6. clarify 的判分落点（跨集统一）：被测系统输出 clarify（轻确认）时记"非静默"，单列统计、不计入拒识率分子、不计入 FAR（与 1.3.4 口径一致）；CoDeTT 映射中 clarify→不计入 4 动作 ACC，单列"clarify 率"列监控——否则公开集会把 clarify 误算成误响应，与 1.3 口径打架。
  7. 看板汇总：列 = 数据集 × S 子类（S1/S2/S3/S4/self-talk 单列），行 = 被测系统/版本；与 4.2.2 自建集同表、分列来源。

运行机制：

  • 统一离线评测 harness（Docker + 固定 GPU RTX A6000，对齐 HumDial 官方评测环境规范）；每次模型/规则/提示词变更全量回归，周度出趋势。
  • 对标坐标（HumDial Track II 官方榜单，整系统口径）：冠军 cookie_asr（Transsion）Rejection Total Score 72.2 / 打断 79.3 / 总分 76.6；官方 Baseline 拒识 35.2 / 总分 56.4。本模块承诺目标为子集级（SDO ≥ 90% / TPS ≥ 95%，见 1.3.5）；榜单分数仅作参照坐标（总分 60% 分量不由本模块决定），不写承诺值。

4.4 方案穿刺

"穿刺"＝在正式立项前，用最小代价把方案的关键不确定性逐个扎穿。四个阶段，每阶段带 Go/No-Go 门槛：

阶段 0：公开集基线（0a + 0b，合计约 1 周）

  • 0a（3–4 天，三套公开集先行）：把候选链路（Silero VAD + CAM++ 声纹 + Paraformer 流式 + L2 端侧裁判）串成离线 harness，接入 CoDeTT + WearVox + ChorusDuplex（三套 HuggingFace 公开、无申请依赖），跑通判分与看板。
  • 0b（2–3 天，HumDial 到位后）：下载 FDBench Humdial-Track2-Test.zip（README 分布表已确认：拒识 2,000 = URB/PH/TPS 各 600 + SDO 200），解压核对子类标签后复用官方评测脚本跑分；标签缺失再走邮件申请（备份路径）。
  • 产出：基线表（S1–S4 分子类拒识率 / FAR / SMR / self-talk 静音率），对照 HumDial 官方榜单（Baseline 35.2 / 冠军 72.2）与 WearVox 论文口径（整体准确率 29%–59%）定位。
  • No-Go：公开集拒识率 < 70% 且误差无法归因到具体层 → 先补前端（空间/声纹）再谈裁判。

阶段 1：延迟穿刺（约 1 周）

  • 全链路时延分解实测：VAD（<30 ms）+ partial ASR 首词（200–300 ms，不等 final）+ L1（<10 ms）+ L2 端侧裁判（10–50 ms）→ 静默判定合计 ≤ 500 ms 闭合；L3 快分支（Jev，~300 ms）与强分支（LLM，100–500 ms）均异步。
  • 门槛：正常响应首延迟 P90 ≤ 800 ms（不因裁判显著变慢）；应静默样本的静默决策窗 ≤ 500 ms；S0 真指令不被误吞（FRR 承诺 ≤ 3%，内部目标 ≤ 2%）；URB/PH 域回归无退化（时机判定归语义 VAD，本模块只验证不引入打断）。
  • 穿刺点：L3 不阻塞静默判定与正常链路——静默/放行由 L1+L2 主判；L3 异步复判：快分支（Jev）~300 ms 出结果，强分支（LLM）超时 300 ms 即回退快分支结果（不回退端侧 L2，避免重复判定）。

阶段 2：对抗穿刺（约 2 周）

  • 8 类困难 case 逐项验证（用尺子2 先导批，每类 ≥ 50 条）：
  1. side-talk 含"帮我/唤醒词"字样（对象是旁人）；
  2. 旁人喊主用户名字后继续说话；
  3. 主用户背对/侧身对旁人说话；
  4. 电视/播客中的指令式台词（B3）；
  5. 双说话人抢话 + 主用户附和（URB 嵌套；时机归语义 VAD，本模块验证不误判为归属问题）；
  6. self-talk 带完整请求句式（"这个放哪来着"）；
  7. 系统提问后的旁人抢答；
  8. 中英混说的 SDO。
  • 每条错误归因到层（身份层错 / 语义层错 / 时序层错 / 延迟超限），反哺 L1 阈值与 L3 提示词。

阶段 3：真机 A/B（约 2 周）

  • 真机 A/B 分两路：音箱（≥ 10 户家庭，含电视开/关两态，每户 ≥ 3 h）与手机（≥ 15 人，街道/车内/办公室，每人 ≥ 2 h）；眼镜真机为补充可选。
  • 指标：主观打扰率（用户报告"抢话/插嘴"次数/小时）、误执行次数（高危，必须为 0）、公开集回归无退化。
  • Go 门槛：S1–S4 分场景拒识率达标（1.3.5 目标）且误执行 = 0；S0 侧 FRR 承诺 ≤ 3%（内部 ≤ 2%）；FAR 按加权公式实算（监控，不设独立门槛）；主观打扰报告 ≤ 0.5 次/小时；时机类（误打断率 ≤ 8%，参照 Gander FD-Bench v3 抢话 8.0%）由语义 VAD 承担、仅回归。
