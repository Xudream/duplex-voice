# S1（主用户→旁人）判定规则与评测用例设计

> 版本：v1.0 · 2026-11-17 ｜ 上位文档：`docs/拒识sideTalk设计文档.md` §1.3（场景定义与指标）、`docs/v2/sideTalk-技术洞察-2026Q4.md`（对齐公开口径）
> 适用范围：家庭音箱（远场、多成员）、手机（近场、常伴随外放）；眼镜为预留场景，本设计给接口不给组量

---

## 1. S1 到底是什么：一句话与三个必要条件

**一句话**：主用户在当前会话中，把语音**投向一个具体的人**（而非设备），系统应 **silent_record**（不响应，但把这句话作为上下文记下来）。

三个必要条件（缺一即不是 S1）：

| # | 条件 | 判据 | 反例 |
|---|---|---|---|
| 1 | **说话人是主用户** | 声纹命中（闭集判定） | 旁人说 → S2/S3；电子源 → S4 |
| 2 | **受话人是一个具体的人** | 有第三方指称、或存在"人—人"交互语用（递物、家务、吩咐） | 无对象 → self-talk；对象是设备 → S0 |
| 3 | **系统当前不产生响应义务** | 不承接系统上一句、不含唤醒词/助手名 | 承接系统提问 → S0 |

> 条件 2 是 S1 的**定义核心**，也是它与 self-talk 的唯一分界：self-talk 是"没人听"，S1 是"有别人在听，只是不是设备"。

## 2. 判定链：五层信号与一步决策树

### 2.1 五层信号（按可靠性排序，不按采集顺序）

| 层 | 信号 | 可靠性 | 在 S1 判定中的作用 | 取不到时的降级 |
|---|---|---|---|---|
| ① 身份层 | 主用户声纹（ECAPA/CAM++ 类）、注册状态 | **最高**（文本无关） | 先分流：非主用户 → 不进 S1 | 降级到距离 + 声纹聚类 |
| ② 空间层 | DoA（音箱环形麦阵）、近讲能量比/双麦声道差（手机）、远场混响特征 | 高 | 朝向偏离设备 → 指向人的概率升高 | 降级到语义 + 时序 |
| ③ 语用层 | 第三方指称（"妈/宝宝/你"）、人—人动作（递/拿/放/帮）、吩咐句式（"把 X 给我"） | 中—高 | S1 的主证据（唯一能区分"同形命令"的语义线索） | 必须存在，否则进 clarify 分支 |
| ④ 时序层 | 是否承接系统上一句、是否在系统播报中、是否紧跟随设备提问 | 中 | 承接 → S0；播报中且无衔接 → S1 概率升高 | 降级到语用层 |
| ⑤ 上下文层 | 会话话题连续性、当前任务槽位是否待填、屏幕/设备态（手机前台应用） | 中—低 | 消解"半同形"（同一话题内的旁白） | 不参与强判 |

**关键设计原则**：① ② 决定"能不能进 S1"，③ ④ 决定"是不是 S1"。**只靠声学永远判不出 S1**（S1 与 S0 声学同形），只靠语义也判不出（文本也同形）——必须"声学定位 + 语用定性"两条腿。

### 2.2 决策树（可直接实现为规则基线，也是标注员的判定流程）

```
输入：一句话 + 声纹结果 + DoA/近讲 + 系统状态 + 会话上下文
│
├─ Q1 声纹命中主用户？
│   ├─ 否 → 是电子源？是→S4；否→与主用户有交流关系？是→S2；否→S3      【S1 不适用】
│   └─ 是 → 继续
│
├─ Q2 含唤醒词 / 助手名 / 明确设备指称（"小X"）？
│   ├─ 是 → S0（放行）——即使句中还有旁人指称，唤醒优先
│   └─ 否 → 继续
│
├─ Q3 承接系统上一句（答句/追问/槽位补充）且无语用冲突？
│   ├─ 是 → S0
│   └─ 否 → 继续
│
├─ Q4 有第三方指称或人—人语用（吩咐/递物/家常）？
│   ├─ 是 → 继续 Q5
│   └─ 否 → 无交流对象？是→self-talk（静默，不记）；否→低置信，进 Q6
│
├─ Q5 空间/时序证据是否一致？
│   ├─ 朝向偏离设备 或 处于播报中且话题无关
│   │     ├─ 一致 → S1（silent_record），置信高
│   │     └─ 矛盾（朝向设备却对旁人说话）→ S1 + 低置信标记（评测单列"矛盾样本"）
│   └─ 无空间信号 → 依语用强度：强（有称呼）→ S1；弱 → Q6
│
└─ Q6 低置信分支（不得一刀切静默）
    ├─ 含请求句式 或 可能承接系统 → clarify（轻确认，出声不执行，单列 clarify 率）
    └─ 否则 → silent_record（记录但不响应）
```

**为什么 Q6 必须存在**：S1 的最高代价不是误静默，而是把真指令当旁白吞掉（FRR）。clarify 是唯一"可逆"的错误处理方式——出声但不动手。

### 2.3 置信度分级（用于分层报告与阈值标定）

| 等级 | 判据 | 期望动作 | 评测用途 |
|---|---|---|---|
| **H 高** | 有声纹 + 空间偏离 + 显式第三方指称 | silent_record | 主指标分母（S1 拒识率） |
| **M 中** | 有声纹 + 语用明确，但空间信号缺失 | silent_record | 主指标分母 |
| **L 低** | 语用模糊、或空间与语用冲突 | clarify 或 silent_record（允许两种都算对） | 单列"模糊集"，不进主指标 |
| **X 排除** | 声纹未命中、或含唤醒词、或承接系统 | 不计入 S1 | 用于边界对照 |

**评测纪律**：主指标只统计 H + M；L 集单独报"歧义处理率"，X 集进 S0/S2/S3/S4。

## 3. 边界：S1 与七个邻居的判据与反例

### 3.1 边界矩阵

| 邻居 | 一句话判据 | S1 侧特征 | 邻居侧特征 | 典型反例（易错） |
|---|---|---|---|---|
| **S0 真指令** | 这句话有没有"设备义务" | 无唤醒词、不承接上一句、受话人是人 | 有唤醒词 / 承接系统提问 / 待填槽位 | "把空调调到 26 度"（对设备）vs "把空调遥控器递给我"（对人）——**同一句式，受话人不同** |
| **S0_guest 访客指令** | 说话人对设备下指令，但不是机主 | 说话人是主用户 | 说话人是访客，且带唤醒词 | 客人说"小X，放首歌"——不是 sideTalk，是权限问题 |
| **S2 旁人→主用户** | 谁对谁说 | 说话人是主用户 | 说话人是旁人，受话人是主用户 | "你手机响了"（家人提醒你）——容易误贴 S1 |
| **S3 旁人↔旁人** | 主用户是否参与 | 主用户是发起方 | 主用户完全不在场 | 客厅两家人聊天，你在厨房 |
| **S4 媒体/电子人声** | 声源是人还是设备 | 人声、近场、有呼吸/口误 | 电子音、无呼吸、可检测到播放中 | 电视剧台词"把枪放下"被当 S1 标注（应为 S4） |
| **backchannel 附和** | 是否争夺话轮 | 寻求对方回应（要动作/要回答） | 只表达"我在听"（嗯/对/好） | "嗯"（附和，属语义 VAD）vs "嗯，你放那儿吧"（S1） |
| **pause 停顿** | 话轮是否结束 | 语义完整、有受话人 | 句中犹豫、语义未完 | "那个……"（停顿）vs "那个，你帮我拿一下"（S1） |
| **self-talk 自言自语** | 有没有交流对象 | 有第三方在场/可指称 | 无对象、无指称、常为自我提醒 | "钥匙放哪儿了"（自言自语）vs "老公，钥匙放哪儿了"（S1） |
| **barge-in 真打断** | 是否要接管设备 | 不针对设备 | 针对设备、要求改变播报 | 播报中说"等一下"（打断，属主链路） |

### 3.2 三种"合法歧义"，必须写进标注规范而不是靠标注员猜

1. **同一句、不同系统状态**：系统 idle 时对旁人说 = 不开始；系统 speaking 时对旁人说 = 是否暂停/恢复。CoDeTT 的做法是把 Side-talk 同时放进 Maintain 与 Dismiss 两个动作下【已核】——我们也必须**按状态分别打动作标签**，不能只打场景标签。
2. **同一句、两种受话人**（"帮我把灯关了"）：如果主用户同时面向设备又面向旁人，动作取决于谁被满足——标注规则：**以"是否要求设备执行"为准**，要求设备执行 → S0；只在向人描述 → S1。
3. **媒体里的第二人称**（电视里"你好，帮我……"）：一律 S4，不因为句子像指令就标 S1。

### 3.3 边界判定的操作化顺序（标注员按此顺序问，不许跳步）

```
① 说话人是谁？（声纹/听感）      → 非主用户：直接进 S2/S3/S4
② 有没有唤醒词/设备指称？        → 有：S0
③ 是不是回答系统刚说的话？        → 是：S0
④ 这句话想让谁做动作/给谁听？     → 人：S1；设备：S0；没人：self-talk
⑤ 系统当时在说话吗？            → 在：动作标签加 "during-speech"，期望可能是 stop/resume
⑥ 有没有媒体证据？              → 有：S4（即使句子像人声指令）
```

## 4. 评测用例设计：先定维度，再定族，最后定格子

### 4.1 七个正交维度（覆盖 = 维度的笛卡尔积上取覆盖，不是随机撒）

| 维度 | 取值 | 为什么必须覆盖 |
|---|---|---|
| D1 说话人 | 主用户 / 访客 / 第三方成人 / 儿童 / 多说话人混合 | 儿童声线与成人差异大，是声纹最薄弱环节 |
| D2 受话对象 | 设备 / 特定人（配偶/孩子/客人）/ 群体 / 自己 / 不明确 | S1 只在"特定人"上有定义 |
| D3 空间 | 近场正对 / 近场侧向 / 远场正对 / 远场侧向 / 跨房间 | 手机与音箱的差异几乎全在空间维度 |
| D4 系统状态 | idle / speaking / 刚停止（0–2 s）/ 恢复中 / 播放媒体 | 同一句在 speaking 时的正确动作不同 |
| D5 语用 | 请求 / 命令 / 陈述 / 疑问 / 附和 / 犹豫 / 呼唤（称呼） | 只有"呼唤 + 请求"才是高置信 S1 |
| D6 内容同形度 | 与 S0 完全同形 / 半同形（只差称呼）/ 非同形（明显家常） | 同形样本是 S1 的核心难度 |
| D7 干扰 | 无 / 电视外放 / 音乐 / 厨房噪声 / 回声 / 双人同时说 | 真实家庭的主场景 |

> **覆盖的定义**：不是"每个维度都有样本"，而是**每个"族 × 关键维度"的格子都有下限样本**（见 §5.2）。

### 4.2 十二个 S1 用例族（每族给出构造要点与反例要求）

| # | 族 | 构造要点 | 期望动作 | 必须配的反例 |
|---|---|---|---|---|
| F1 | **称呼型吩咐** | "妈，把盐递给我"；含明确称谓 + 人—人动作 | silent_record | 同词去称谓 + 加唤醒词 → S0 |
| F2 | **同形命令型** | "把空调调到 26 度"（对家人复述） vs 对设备说 | silent_record | 同句对设备 → S0（**配对样本**） |
| F3 | **指代型** | "这个帮我放桌上"（指物品，不是对设备） | silent_record | 指代 + 面向设备 → S0/clarify |
| F4 | **家务流水句** | "你先把衣服收了，我一会儿洗碗" | silent_record | 单句无对象 → self-talk |
| F5 | **远场/跨房间** | 主用户在厨房对客厅家人喊话 | silent_record | 跨房间喊设备（含唤醒词）→ S0 |
| F6 | **播报中旁白** | 系统播报天气时，用户对家人说"晚上吃啥" | silent_record（不中断汇报）+ 播报应继续 | 播报中说"等一下" → barge-in（主链路） |
| F7 | **混合轮** | 一句话里既对家人说又对设备说："妈你等一下——小X，声音小点" | 拆两段判定，设备段 S0 | 整句当 S1 → 会吞掉指令（错误标注） |
| F8 | **电话/视频** | 用户接电话，说"我一会儿回给你" | silent_record | 电话中说"小X 挂断" → S0 |
| F9 | **儿童对家长** | 孩子说"妈妈，我要喝水" | silent_record | 孩子对设备说"小X 讲故事" → S0_guest（另册） |
| F10 | **self-talk 临界** | "钥匙放哪儿了……"(无对象) | 静默，不记上下文 | 加称谓 → S1 |
| F11 | **媒体临界** | 电视台词"把枪放下"、短视频"帮我点个赞" | S4（不是 S1） | 真人模仿电视腔 → 仍是 S1（考声学判别） |
| F12 | **模糊/低置信** | "把它关了吧"（对人或对设备都可能） | clarify 或 silent_record 均可 | 强上下文（槽位待填）→ 应判 S0 |

### 4.3 反事实配对（比堆样本更能证明"判得对"）

三组配对，每组同文本、只改一个变量：

| 配对 | 固定 | 改变 | 验证什么 |
|---|---|---|---|
| P1 受话人对 | 同一句文本、同一说话人、同一房间 | 受话人：设备 / 家人 | 模型是否真的在判"对象"，还是在判"文本" |
| P2 状态对 | 同一句、同一受话人 | 系统 idle / speaking | 动作是否随状态切换（CoDeTT 式 Maintain vs Dismiss） |
| P3 距离对 | 同一句、同一受话人 | 近场正对 / 远场侧向 | 是否依赖空间捷径；去掉空间后掉多少 |

**判分**：配对准确率（pair accuracy）= 一对同时判对才计分。这一项能把"永远静默"策略直接打到 ≤50%。

### 4.4 组量：先算 CI 再定条数

Wilson 95% 半宽 ≈ 1.96·√(p(1−p)/n)，p≈0.9 时：

| 目标半宽 | 所需 n（每场景） | 说明 |
|---|---|---|
| ±4.2pt | 200 | 仅够看趋势（HumDial SDO 测试集就是这个量级） |
| ±2.6pt | 500 | **单族下限**：可以报"某族是否达标" |
| ±1.9pt | 900 | **S1 主指标下限**：与现有尺子 986 条一致 |
| ±1.3pt | 2,000 | 模型间 <3pt 差异才可分 |

**S1 建议组量（v2 尺子）**：主集 **1,000 条**（H 700 + M 300）+ 模糊集 **200 条** + 边界对照 **400 条**（S0 200 / self-talk 100 / S4 100）= **1,600 条语音**；另有 **300 对**反事实配对（P1/P2/P3 各 100 对），**从既有录音中剪辑复用，不额外采集**。

## 5. 全场景覆盖怎么证明（不是"我觉得覆盖了"）

### 5.1 覆盖矩阵（manifest 自带，脚本可校验）

每个样本在 JSONL 里带 7 个维度字段 + 族字段：

```json
{"id":"s1_f2_0007","scene":"S1","family":"F2","speaker":"main","addressee":"person_spouse",
 "space":"far_offaxis","sys_state":"speaking","pragmatics":"command","isomorph":"full",
 "interference":"tv","conf":"H","pair_id":"p1_0012","audio":"s1/f2/0007.wav",
 "expect_action":"silent_record","note":"复述给家人，文本与 S0 同形"}
```

**覆盖判据（五条，缺一不算覆盖）**：

1. **族覆盖**：F1–F12 每族 ≥ 40 条（H/M 合计）。
2. **格子覆盖**：`族 × D6 同形度` 的 12×3 = 36 格，每格 ≥ 10 条（同形样本是核心，不允许为空）。
3. **状态覆盖**：`族 × D4` 的 12×5 = 60 格，每格 ≥ 5 条，且 idle 与 speaking 两态各 ≥ 30%。
4. **配对覆盖**：P1/P2/P3 各 ≥ 100 对，且每对两侧的 conf 等级一致（否则差异来自难度而非变量）。
5. **反例覆盖**：每族的"必须配的反例"（表 4.2 最后一列）各 ≥ 20 条，且落在对照集里而不是 S1 集里。

### 5.2 覆盖自检脚本（放在 `tools/check_coverage.py`）

```python
# 伪代码：读 manifest → 打表 → 断言
need_family = {f"F{i}": 40 for i in range(1, 13)}
need_cell   = 10        # 族 × 同形度
need_state  = 5         # 族 × 状态
need_pair   = 100       # 每种配对

errs = []
for fam, n in Counter(x["family"] for x in rows if x["scene"] == "S1").items():
    if n < need_family[fam]: errs.append(f"{fam} 仅 {n} 条")
for (fam, iso), n in Counter((x["family"], x["isomorph"]) for x in rows).items():
    if n < need_cell: errs.append(f"{fam}/{iso} 仅 {n} 条")
for (fam, st), n in Counter((x["family"], x["sys_state"]) for x in rows).items():
    if n < need_state: errs.append(f"{fam}/{st} 仅 {n} 条")
for p, n in Counter(x["pair_id"][:2] for x in rows if x.get("pair_id")).items():
    if n < need_pair * 2: errs.append(f"配对 {p} 仅 {n} 条")
assert not errs, "\n".join(errs)
```

**跑通这条断言，才有资格说"覆盖了"。**

### 5.3 泄漏检查（防"偷分"，比覆盖更容易被忽略）

| 泄漏 | 表现 | 检查方法 | 修法 |
|---|---|---|---|
| 声纹泄漏 | S1 全是家人、S0 全是机主 → 靠声纹就能分类 | 统计 `speaker` 分布；S1 与 S0 的说话人分布必须重叠 | S1 也由机主录制（本来就要求机主说） |
| 词表泄漏 | S1 出现"递/妈"、S0 出现"空调/播放" → 词表捷径 | 训练 n-gram LR，若 F1 > 0.85 即有泄漏 | 同形样本（F2）比例 ≥ 30% |
| 房间泄漏 | S1 全在客厅、S0 全在厨房 → 靠混响分类 | 比较各房间的 S1/S0 比例 | 每房间各采两类 |
| 时长泄漏 | S1 更长/更短 | 统计时长分布 KS 检验 | 对齐 + 裁剪 |
| 位置泄漏 | S1 全侧向、S0 全正对 | 交叉表 | 补正对/侧向各半 |

## 6. 判分：S1 这一项到底怎么算分

| 指标 | 分母 | 说明 |
|---|---|---|
| **S1 拒识率** | H+M 的应静默样本 | 主指标；clarify 不算对（clarify 单列） |
| 误执行 | 应静默样本 | 触发工具调用即计；**必须为 0** |
| **上下文完整性** | S1 正例中"后续被引用且能答对"的比例 | 检验 silent_record 是否真记了（不记 = 协议用错） |
| 配对准确率 | P1/P2/P3 各 100 对 | 防固定动作策略 |
| 模糊集处理率 | L 集 200 条 | 只报分布（clarify/silent 各多少），不设目标 |
| 静默决策延迟 | 应静默事件 | P50 ≤ 390 ms；与判停共用一次前向 |

**分层报告（必须同时给）**：按 `family`、`isomorph`、`sys_state`、`conf` 四个切片各报一次——只看总分会掩盖"同形样本全错"这种致命问题。
