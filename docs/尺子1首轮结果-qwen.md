## 4. 三个发现

### 4.1 最大的杠杆不是模型，是"喂哪段文本"（+19.2pt，零代价）

HumDial 的样本是「先两轮对助手的提问 + 最后一段转向旁人」，我最初把整段拼成一条转写喂给模型，模型看到开头两个提问就判"该响应"：

> qwen-plus 的失败理由原文：**"连续两个技术问题，明显对助手提问"** → respond

humdial/S1 因此是 **0%**。改成只喂当前 VAD 段（`--text-mode last`）后：

| | humdial/S1 | 整体 S1 | FRR |
|---|---:|---:|---:|
| 整段 | 0% | 38.3% | 5.0% |
| 当前段 | 55% | 57.5% | 6.7% |

**这不是模型问题，是协议问题**：真实产品里 VAD 已经分了段，只该判当前段。尺子1 的 runner 默认值已改为 `--text-mode last`。

### 4.2 提示词规则再加 +18.3pt，但代价是 FRR 翻三倍

v2 加了两条规则（多说话人以最后一句为准、对旁人陈述/念稿不算请求）：

| | S1 | S2 | S3 | FAR_w | FRR |
|---|---:|---:|---:|---:|---:|
| 当前段 + v1 | 57.5% | 32.2% | 63.3% | 45.4% | 6.7% |
| 当前段 + v2 | 73.3% | 57.8% | 75.0% | 29.1% | 16.7% |
| 当前段 + v3 | 75.8% | 58.9% | 71.7% | 28.7% | 21.7% |

**拒识率是被"更爱闭嘴"换来的**，不是判得更准。这条曲线说明：靠 prompt 调不动工作点，只能整体平移。

### 4.3 置信度不可用：模型自信地错，工作点扫不出来

qwen 输出的 `confidence` 只落在 **0.95 和 0.98** 两个值上，阈值扫描完全不动（0.05→0.95 的结果一模一样）。
改让模型输出 `p_silent`（0–100 连续值）后分布是双峰的：97（181 条）vs 5/10/15（154 条）——**看起来可分，实际不可用**：

| 指标 | 数值 |
|---|---|
| S0（应响应）p_silent 中位数 | 5 |
| S1–S3（应静默）p_silent 中位数 | 97 |
| AUC（p_silent 区分应静默/应响应） | **0.780** |
| S0 中 p_silent ≥ 90（**自信地判错**） | **22%** |
| S0 中 p_silent ≤ 20 | 77% |

那 22% 自信判错的样本在任何阈值下都静默 → **FRR 的地板就是 21.7%**，无论阈值怎么调都过不了 5% 的门槛。

## 5. 分集诊断（当前段 + v3）

| 集 | S1 | S2 | S3 | 判断 |
|---|---:|---:|---:|---|
| chorus | 78% | 87% | 93% | 可用；TTS 合成、声学干净 |
| wearvox | 78% | — | 57% | S1 可用；旁人对旁人（S3）偏弱 |
| humdial | 65% | **29%** | — | 真实中文数据，S2 几乎不可分 |

humdial/S2（旁人对该用户说）只有 29%：**没有说话人标记时，"旁人问他"和"他问助手"在文本上无法区分**——这不是模型能力问题，而是文本通道的信息上限。要解决只能加空间线索（双声道/DoA）或说话人分离。

## 6. 结论

| 判据 | 要求 | 实测最好 | 结论 |
|---|---|---|---|
| S1 拒识 | ≥ 80% | 75.8% | ❌ 差 4.2pt |
| FRR | ≤ 5% | 21.7%（地板） | ❌ 差 16.7pt |
| 误执行 | 0 | 0 | ✅ |
| invalid | ≤ 1% | 0.53% | ✅ |
| 延迟 p50 | ≤ 300 ms（端侧）/ ≤ 800 ms（云） | 1044 ms | ⚠️ 云端可用、端侧不可用 |

**通用 Qwen 直接当裁判：淘汰。** 但这不是"这条路不通"，而是三条明确的改进路径：

1. **专用小模型**（0.6B–4B 微调）：S1 训练数据来自自建集（FDBench 的 SDO 训练集是 0 条），这是唯一能同时拿到高 S1 和低 FRR 的路
2. **加空间线索**：双声道/DoA 解决 humdial/S2 与 wearvox/S3，文本通道到顶了
3. **模型级联**：0.6B 先筛（低延迟），9B 复判（高精度），这正是 L3 快慢融合的形态

## 7. 复现

```bash
cd ~/repos/projects/duplex-voice/tools/ruler1
DATA=~/.hermes/workspace/ruler1/data

python3 build_manifests.py --dataset all --data $DATA --out manifests   # 加 segments/target_text
python3 make_mini.py --manifests manifests --out manifests/mini.jsonl    # 380 条分层抽

python3 llm_judge.py --manifest manifests/mini.jsonl --backend openai_compat \
  --base-url https://dashscope.aliyuncs.com/compatible-mode/v1 \
  --model qwen-plus --text-mode last --prompt-version v3 \
  --out predictions/qwen-plus-last-v3__mini.jsonl

python3 score.py --manifest manifests/mini.jsonl \
  --pred predictions/qwen-plus-last-v3__mini.jsonl --only-predicted --sweep
```

本轮 6 次运行的原始预测在 `/tmp/r1/pred/`，报告在 `/tmp/r1/reports/`（本地，不入库）。
